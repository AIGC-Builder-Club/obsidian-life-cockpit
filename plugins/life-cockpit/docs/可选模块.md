# 可选模块：秒哒 / 飞书金字塔表格

插件有两根轴是**可选**的：秒哒「5 分钟写作」和飞书金字塔表格。它们和番茄、目标树、账本不一样——接了多两栏东西，不接一个字都不少。

两节的门槛差很多，先看清楚再决定读哪一节：

| 模块 | 现在能不能接 | 需要什么 |
| --- | --- | --- |
| **秒哒** | ⚠️ **暂时只有作者能用** | 见第一节的说明与两个未来方案 |
| **飞书**（主路） | 能，但不是「装上就能用」 | **Convex 后端 + 一台带 `lark-cli` 的执行机**（第三、四阶段） |
| **飞书**（旁路） | 能，零依赖 | 手动往 vault 放一份快照 JSON。**作者自己用得很少**，属降级方案 |

这两节各自独立，按需挑一节读。

---

## 第一节 · 秒哒：⚠️ 目前是【作者自用】

> **先说清楚：这一节你现在多半接不上。**
>
> 秒哒那个「5 分钟写作」APP 是**作者的个人项目**——里面是他自己的快速写作数据，
> 属于日常快速测试性质的应用，没有对外开放注册使用。插件这一侧的接法是通的，
> 但另一头那个项目不是给别人用的，所以第三方拿不到能用的接口地址。
>
> **这不是弃坑，作者给了两条将来能走通的路：**
>
> 1. **开放项目本身** —— 提供秒哒项目源码，或者在云平台上开放「复制为模板项目」的功能，
>    你自己 copy 一个出来，接口地址就是你自己的。
> 2. **按用户自定义「存储码」** —— 基于现有的临时写作笔记存储，把秒哒 5 分钟写作 APP
>    改成按每个用户自定义的**存储码**做备份和拉取：接口里传哪个存储码，就拉哪个存储码的数据。
>    这条落地了，第三方就不需要自己有项目，填一个存储码即可。
>
> 下面的说明**照常有效**——将来上面任一条落地，或者你本来就有自己的秒哒项目，照着配就行。

**要不要接**：你在用秒哒上那个「5 分钟写作」APP（头脑风暴式的——几秒不写就擦掉，手机语音输入）。用它，这一节就把你每天写的那些段落搬进 vault。

**接了得到什么**：一天一页 Markdown，一段写作一个大标题，落在给人看的那一块（默认 `LifeCockpit/秒哒写作/`）。每段标着几点写的、哪种模式（经典 / 快速 / 语音）、写了多少字、擦除倒计时是 5 秒还是 12 秒、有没有撑到达标。**原文一字不改**——语音识别错的字也照抄，因为这一层只是落地区，润色是你自己（或者以后某个 Agent）的事。

**不接损失什么**：vault 里少这几页。别的什么都不受影响。

### 接上只要两步

0.19.0 起**插件不再预置任何地址**——预置它等于把某个具体的秒哒项目暴露在公开仓库里。所以：

1. **填接口地址**。从你自己的秒哒应用里拿它的 **PostgREST 地址**，指向写作记录那张表，形如 `https://…/rest/v1/<表名>`。这是一个 PostgREST 风格的接口（请求带 `accept-profile: public`）——Supabase 那一套，不是作者提供的公共服务。地址里带着项目 ID，所以只能你自己填，插件不猜。
2. **填 apikey**。就是你那个秒哒应用（Supabase 项目）的匿名 key，同时用作 Bearer。形状是一段 JWT：`eyJ` 开头、两个点分成三段。粘进来带的换行、空格、引号、`Bearer ` 前缀会被自动去掉——手抄多带的一个换行换回来的是一个 401，而它长得和「key 填错了」一模一样。

两样都填在**设置 → 交班 · 复盘 → 秒哒「5 分钟写作」**。apikey 也可以不走设置，设环境变量 `LIFE_COCKPIT_MIAODA_KEY`；两处都空就是没配这条路。**apikey 不进仓库**——插件不内置任何密钥，这个仓库是公开的。

**怎么验证接上了**：同一页设置最底下有一行状态。地址没填时它说的是：

> 还没填接口地址。填在 设置 → 秒哒 → 接口地址：你那个秒哒应用的 PostgREST 地址，指向写作记录那张表（形如 `https://…/rest/v1/<表名>`）。地址里带着项目 ID，所以得由你自己填，插件不猜。

填齐之后按「现在拉一次」（或命令面板搜「拉一次秒哒」）。成功的话弹一条通知，长这样：`秒哒：新写 12 段、跳过 3 条空白记录，落在 2 天（2026-08-20 … 2026-08-21）。`

### 三条纪律

这三条是这个模块的全部设计。它们存在的理由只有一个：落地区是**给你看、给你改**的，机器不许跟你抢那一页。

1. **搬走的段落不补写。** 你把某一段整理进飞书表格（或者随便哪儿）然后从落地页删掉之后，下一次拉取看到的是「这条我写过」，于是不再写回来。同步索引 `_同步索引.json`（就在落点目录里）记住每一条写过没有、写去了哪一天。
2. **手写的段落不碰。** 插件认段落靠「标题下面跟着 `- 秒哒ID：` 那一行」。你自己写的小节没有这个身份证，永远原样不动；你在某段正文里加的小标题也不会把那一段劈成两半。
3. **重复拉取不写盘。** 同一条拉十次得到同一份字节，逐字节比对相同就是零写入。这些文件落在你的 vault 仓库里，假写入等于给 git 制造空 commit——页首说明里连「拉取于」都不写，就是为了这个。

### 默认是什么状态

- 那一栏**默认开着，但没有地址也没有 key**——开着不等于会发请求，一台新机器上它什么都不做。
- **自动拉取默认关**：定时往外网发请求这件事该由人明确点头。开了之后默认每 60 分钟一次（下限 5 分钟），增量只问「上次之后动过的那几条」，翻页翻到底。
- 关着不影响手动拉：命令面板随时可以「拉一次秒哒」；页面看着不对时用「整份重拉」当逃生口。
- 点开又没写的空白记录默认不落盘（实测 188 条里有 27 条是这种——落地区里塞一堆空壳，第一眼全是噪音），想收全有开关。
- 一段属于哪一天**按「开始写」那一刻算**，并且跟驾驶舱的账本日共用同一个换日点（默认 04:00）——深夜写的那段跟着当天走。

## 第二节 · 飞书金字塔表格

**边界先说死**：**记录仍然发生在飞书上。** 插件不在 Obsidian 里造第二张任务表，**也不直接调飞书 OpenAPI**——它不碰 app id / app secret / user token。真正读写飞书的自始至终是官方 `lark-cli`，跑在一台外部执行机上。

但「插件不直接调飞书 API」不等于「插件不需要后端」。**这一栏有主路和旁路两条，门槛差得远：**

### 主路：插件触发 → Convex job → 执行机推快照 + 写回【总结】页

插件里有四个入口（面板、设置页、命令面板、React 数据台）会调 Convex 的 `feishu:requestPull` 起一个 job，
订阅 `jobs:watch` 看进度，用 `jobs:active` 在 Obsidian 重启后接回现场。执行机按 `jobId + attempt`
**先推最新快照、再写【总结】页**并回执。

**这条路要 Convex 后端 + 一台完成过 `lark-cli auth login` 的机器**，属于第三、四阶段，
**不是「装上就能用」**。怎么配见 [`backend/life-cockpit/SETUP.md`](../../../backend/life-cockpit/SETUP.md)。

### 旁路：手动往 vault 放一份快照 JSON

不接后端也想让这一栏不空，就手动放一份导出好的快照 JSON 进去。零依赖：不需要 lark-cli、不需要 Convex、不需要任何凭据。

> ⚠️ **这是降级方案，不是推荐路径。** 仓库主人自述这条旁路**他自己用得很少**——
> 日常真正在跑的是上面那条主路。所以：想认真用飞书这一栏，请照主路配；
> 只是想先看看这一栏长什么样，才走旁路。

**接了得到什么**（两条路一样）：复工强提醒页、驾驶舱面板和睡前复盘素材包里多一栏「表上安排了什么、做完了没有」。没做完的排前面——强提醒页拦着你那几秒要看的是还欠什么。

**不接损失什么**：就少这一栏。读不到快照**不是错误，是一种状态**——那一天只是没有飞书这一栏，番茄、目标树、复盘全部照跑。

下面讲的是**旁路**那份 JSON 的放法和格式（主路推上来的快照走的是同一套格式，所以这一段两条路都适用）。

### 快照放哪儿

**设置 → 交班 · 复盘 → 飞书金字塔表格 → 快照目录**，默认 `LifeCockpit/飞书快照`。

找文件的顺序是三级：

1. `<快照目录>/<今天>.json`
2. `<快照目录>/latest.json`
3. 目录里日期最大的那份 `YYYY-MM-DD.json`

**第三条是常态，不是兜底。** 快照是隔几天才更新一次的东西，只认当天文件的话这一栏一年里有大半年是空的——而它要回答的「我最近都在做什么」恰恰不需要当天。读到的不是今天那份时，面板会写明「这是表上最近有记录的一天」。

### 格式：直接吃导出管线的产物

首选就是把导出管线产的 `all_tasks.json` **原样拷过来，一个字节都不用改**。三种形状都认（约定定得复杂，就没人遵守）：`{generated_at, all_tasks}`、`{tasks}`、裸数组。

可直接复制的最小样例（**编的数据**，换成你自己表上的内容）：

```json
{
  "generated_at": "2026-08-20T08:00:00+08:00",
  "all_tasks": [
    {
      "sheet": "2026年08月18日 周二",
      "text": "把上周的实验数据整理成一张对照表",
      "status": "已完成",
      "difficulty": "中难",
      "side": "工作内容"
    },
    {
      "sheet": "2026年08月18日 周二",
      "text": "读完搁了很久的那本书的前三章",
      "status": "完成了一部分",
      "difficulty": "低难",
      "side": "个人兴趣"
    },
    {
      "sheet": "2026年08月19日 周三",
      "text": "给自行车做一次保养",
      "status": "完全没去做",
      "difficulty": "低难",
      "side": "个人兴趣"
    }
  ]
}
```

每一条用得上的是五个字段：

| 字段 | 说明 |
| --- | --- |
| `text` | 任务原文。**空白的不是任务**，会被丢掉 |
| `sheet` | 日期从它解：`2026年08月18日 周二` → `2026-08-18` |
| `status` | 四选一：`已完成` / `完成了一部分` / `完全没去做` / `未知状态` |
| `difficulty` | `高难` / `中难` / `低难`；判不出来留空串 |
| `side` | `工作内容` / `个人兴趣`；判不出来留空串 |

也可以直接给 `day`（`YYYY-MM-DD`），给了就不解 `sheet`。`generated_at` / `source_url`（也认驼峰 `generatedAt` / `sourceUrl`）可选，填了显示在面板上——「这份快照有多旧」是人一眼就想知道的事。除这些之外的字段一律原样忽略，导出产物里的 `rules` / `diagnostics` / `ignored_cells` 留着不碍事。

两条读法上的规矩：

- **解不出日期的不算进任何一天**（模板页 `模板(直接创建副本)` 就是这种）。那不是错误。
- **认不出来的状态一律落到「未知状态」，不假装已完成。**

### 什么不算任务

导出管线的口径（SOP《解析规则》）里，这几种不是任务：**空文本**、光杆的 `50` / `300` / `1000` **默认分值**、以及形如 `(1000)（1/5）` 的**模板分值/配额占位符**（兼容半角/全角括号、任意数字、空格和换行）。

这条判断**必须在压换行之前做**：占位符在表上长的就是 `(1000)` 换行换行 `（1/5）`，把换行压成空格之后再判，它看起来就像一条正经任务了。

为什么值得较真——这不是假想的风险，是仓库里真实发生过的一次事故：**那份快照 177 条里有 38 条是占位符**，全是模板里预填的格子，却全被记成「完全没去做」——「还欠什么」清单里一大截是假的，**完成率被从 54% 压到 42%**。

两点交代清楚：

- 这条规则的执法位置在**导出管线和后端的【总结】页**（那边宁可多滤一道）；**插件读快照时只丢空文本**。所以如果你手写快照，别把模板占位符抄进来——抄了它们就会以任务的样子出现在提醒页上。
- 手写也行——它只是一个 JSON 数组。但**别用模型现编**：这一栏的全部价值在于它是表上的事实。

### 主路怎么配

上面是**旁路**「手动放一份 JSON」的全部。主路（插件触发 Convex job → 执行机推快照 + 写回【总结】页）
