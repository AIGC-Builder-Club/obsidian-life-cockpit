# 人生驾驶舱 Life Cockpit

把日记模板里**画出来**的那张作息表变成**跑起来**的东西：番茄计时、当日 560 分钟进度、禅定模式、模式切换、五行节律表提醒，一本完成任务入账、享乐出账的积分账本，一棵从宇宙级到日内目标的六层目标树，一张给夜班 Agent 产物用的拍板面，一轮把这一天收口的睡前复盘，一套在人飘掉时推一把的推动器，以及一层人不听时会真的打断你的强制干扰。流水、账本、目标树与候选区都落 vault 内文件。

七根轴：**时间**（番茄）、**状态**（积分）、**结构**（目标树）、**交班**（候选区）、**收口**（睡前复盘）、**推动**（推送 / 强提醒页 / 强制休息）、**打断**（强制干扰：连击 / 闪屏 / 锁屏）。

自研插件，直接住在本合集仓库里（和 RefBake 一样），不单开仓库——独立仓库 + submodule 那套只给二开插件（Easy-Git）用。

## 安装

把 `dist/life-cockpit/` 里的 `main.js`、`manifest.json`、`styles.css` 拷进 vault 的 `.obsidian/plugins/life-cockpit/`，重启 Obsidian 后在第三方插件里启用。

只做桌面端（`isDesktopOnly: true`）。

## 本地构建

```bash
cd plugins/life-cockpit
npm ci
npm test          # node --test，覆盖计时状态机 / 节律表判定 / 流水与账本读写幂等 / 目标树拆分与回灌 / 候选项解析与三种拍板动作 / 复盘取数汇总与回写 / 推送五道闸与渠道分发 / 强提醒页与锁屏状态机 / 推荐挑选与轮换
npm run lint
npm run build     # tsc --noEmit + esbuild → main.js
cd ../..
node scripts/update-life-cockpit-package.mjs
```

同步脚本只在内容真变了才写盘，连跑两次第二次应当输出 `already up to date`。

## 命令面板

计时那一摊：`开工（开始 / 接着跑番茄）`、`结束本段（休息照常开始，催促照常继续）`、`今天收工（停掉今天的催促）`、`打开人生驾驶舱`、`开关禅定遮罩`、`切换模式（思考优先 / 加速实践）`、`报一下当前时段`。

账本那一摊：`记一笔积分`、`记一笔享乐消耗`、`打开积分账本`、`撤销最近一笔积分`、`写出积分任务表`、`重读积分账本`。

目标树那一摊：`打开目标树`、`把番茄挂到某个目标上`、`新建日内目标`、`写出目标树`、`重读目标树`。

候选区那一摊：`打开夜班候选区`、`重读夜班候选区`。

复盘那一摊：`睡前复盘（取数 → 出草稿 → 投候选区）`、`打开今天的复盘素材`、`只生成复盘素材包（给夜班用，不出草稿）`。

秒哒那一摊（0.16.0）：`拉一次秒哒「5 分钟写作」`、`整份重拉秒哒（页面看着不对时用）`、`打开今天那一页秒哒写作`。**平时用第一条**——它只问「上次之后动过的那几条」；第二条是逃生口，页面看着不对时把远端有的都补回来。

飞书与 AI 那一摊（0.18.0）：`打开飞书金字塔表格`、`打开飞书【总结】页`、`更新飞书【总结】页（Convex 主路径）`、`重读飞书快照`、`备用：拉一份新的飞书快照（旧 webhook + Easy Git）`、`测一次 AI 接口`、`看 AI 调用记录`。

推动器那一摊：`试推一条（看看渠道通不通）`、`静音 / 恢复推送`、`现在过一遍复工强提醒页`、`今天推荐读什么`、`立刻锁屏（强制休息）`、`开关运行时音乐`。

强制干扰那一摊：`演练一次强制干扰（20 秒）`、`停止强制干扰`。**装完先按前一个**——不然要验「收工前会怎样」得真的坐等二十几分钟，而验一次锁屏还要重新登录一次。

三个 ribbon 图标：计时器打开驾驶舱面板，靶心打开目标树面板，收件箱打开夜班候选区（「睡前复盘」按钮也在这张面板顶上）。

## 禅定盖谁

**禅定 = 一段活干完之后的休息、静心，不是「远离电脑」。**

这一条曾经理解反了。0.6.4 之前的做法是「工作段全屏遮罩」，也就是在人干活的时候，
把 Obsidian 这个**工作台**盖住。可电脑和 Obsidian 是生产力工具，是干活的地方，
不是要躲开的东西；真正该在休息时放下的是手机那类娱乐工具，而那个恰恰是这块遮罩
盖不着的。盖反了的结果是：锁住工作台、放过所有玩具。

所以从 0.6.5 起：

- **休息段盖**——这才是禅定那一段。全屏轮换休息页，倒计时在上面走，Esc 随时退出，**退出不停表**；
- **工作段默认不盖**。要盖得有明确的意思表示：设置里打开「工作段也盖遮罩」长开，
  或者用命令面板的「开关禅定遮罩」临时叫一次（只对当前这一段有效，换段即失效）。

判断规则是纯函数，在 `src/core/zen.ts`，`test/zen.test.js` 盯着。

### 这块遮罩是休息页，不是锁屏

它只盖得住 Obsidian 这一个窗口，挡不住浏览器，更挡不住手机。所以在系统级锁屏没开的时候，
休息页底下会写明这件事——**不让一块遮罩冒充锁屏**。真要锁，走
《强制休息与系统级锁屏》那条路（默认关，见下文）。

### 「进入状态」那一下在哪儿

复工之前先静一静、把心态调回来的那一下，是**复工强提醒页**（R6，默认开、默认停留 8 秒），
不是这块禅定遮罩。两者是一前一后的两件事：禅定收尾，强提醒页开场。见下文《复工前的强提醒页》。

### 休息的表不等人，开工的表永远等人

两侧是反的，而且都不是开关：

- **休息段一律自跑**——休息的钟在工作结束那一刻就已经开始走了。等人点一下才走的休息
  不是休息，是一块停在 05:00 不动的表（AME-231）。
- **工作段一律停着等人**——0.8.0 起「自动开始下一段」那个开关整个删掉了。原话是
  「【开工】永远是 人类手动的行为（【自动开工】永远是无法被接受的！）」（AME-239）。
  删掉而不是改默认值：改默认值救不回已经把 `true` 存进 `data.json` 的机器，
  而且一个能被打开的自动开工开关，迟早会被打开。

停着的表任何时候都看得出是在等人：面板上写「等你开工」、按钮变成高亮的「开工」，
遮罩副标题写「停着 · 按「开工」倒计时才会走」，桌面悬浮框标红并且**不走秒**。
从前遮罩把状态栏那个 `⏸` 一起盖掉了，于是一块停着的表只能被读成「倒计时坏了」。

### 结束本段 ≠ 今天收工（0.10.0）

**0.9.0 及以前，手动【结束】把整套强约束一起关掉了**：表回到 idle，待命清空、强提醒页作废、
干扰归零，然后就那么一直停在那儿。而那颗按钮长得只像「这个番茄我提前结束」。

> 「我发现，在【手动结束一个番茄】之后，不会有后续的【提醒、介入】什么之类的——
>  ta 就那么一直停在那儿了？这个不符合我的预期，我的预期是
>  **【不管是自然完成还是结束；强干扰和提示 仍然会照规则存在的。】**」（AME-258）

0.10.0 把这一件事拆成两件：

| 动作 | 在哪儿 | 做什么 |
| --- | --- | --- |
| **结束本段** | 面板按钮 + 命令面板 | 这一段照实记成未完成，然后**走和跑满一模一样的那条路**：工作段结束 → 进休息（该锁屏就锁屏）→ 休息结束 → 停在工作段等你开工 → 不复工就照常催 |
| **今天收工** | 只在命令面板，且要确认一次 | 表回 idle，今天剩下的强提醒与强制干扰全部停掉。明天第一次开工时一切照旧 |

收工那颗**故意不放进面板**：它是唯一能把催促停下来的动作，应该需要专门找一下才按得到。
「该开工而没开工就应该永远提示」（AME-239）那条规矩没有变——停的不是规矩，是今天。

还有一个洞顺手堵上了：**一秒都没跑过的段结束不了**（休息刚完、工作段停着等人的那一刻就是这种）。
放行的话按一下【结束本段】就换来一段休息——那就是「跳过本段」从后门回来了。那种时候按钮是灰的。

## 重启接得上（0.9.0）

> 我是一个会经常折腾 Obsidian、包括重启 Obsidian 来让各种插件调整和生效的人；所以【Obsidian】重启，是像家常便饭一样的事情。

所以 0.9.0 起，**挂着的预设任务、挂着的目标树节点、跑到一半的那个番茄**都活在 `data.json` 里，
重启之后原样接回来——不用每次重开都重挑一遍。跑着的时候每 15 秒刷新一次时刻，
所以就算 Obsidian 是被任务管理器结束掉的，也只丢最后那十几秒。

难的不是存，是**离开的那段时间算不算专注**。全算的话，关了三小时回来白得三小时（账当场就假了）；
全不算的话，重启一次 20 秒番茄就从头开始（那正是这条 issue 在抱怨的）。所以按段的性质分：

| 关掉 Obsidian 时 | 回来之后 |
| --- | --- |
| 工作段在跑，离开 **≤ 宽限期**（默认 5 分钟） | 原样接着跑，中间那点时间照算 |
| 工作段在跑，离开 **> 宽限期** | **就地冻住**：进度停在关掉那一刻，离开的时间**一秒不算**，回来自己按开工 |
| 工作段停着等人 | 原样停着等人（它本来就没在计时） |
| 休息段在跑，还没到点 | 接着跑——休息按墙上的钟走，人不在正好是在休息 |
| 休息段在跑，已经过点 | **补记那一段休息**（起止时刻都是真的），然后停在「休息结束，等你开工」 |
| 存的是上一个记账日的段 | 整段作废，今天从零开始，不回头补记昨天的账 |

最后三行有两点值得说明：

- **回来之后是「停着等你」，不是「继续跑」。** 离开很久回来和休息结束还没复工是同一种状态，
  所以它一样进待命、一样会被催、复工前一样先过强提醒页——开工永远是人手动的（AME-239）。
- **补记用的是存下来的计划时长**，不是现在设置里的：已经跑过的那一段不该因为你后来改了设置而变长变短。

不想要这套的话：设置 → 番茄 → 重启与状态延续，关掉之后每次启动都是一张干净的表。

## 两种模式的基准时长（0.9.0 对调）

> 我想了一下，似乎【思考优先】应该是 25 分钟的时长基准；而【加速实践】应该是 45 分钟的时长基准。（思考 需要更多的思考和调节时间、连续思考 45 分钟 是不现实的；而【加速实践】更多的是一种冲劲，连续 45 分钟 是一种正常的表现。）

| 模式 | 0.8.0 及以前 | 0.9.0 起 |
| --- | --- | --- |
| 思考优先 | 45 + 10，三个一轮，提醒 45 分钟 | **25 + 5**，四个一轮，提醒 30 分钟 |
| 加速实践 | 25 + 5，四个一轮，提醒 30 分钟 | **45 + 10**，三个一轮，提醒 45 分钟 |

对调的是**整组节奏**（工作 / 休息 / 长休息 / 几个一轮 / 提醒间隔），不是只挪一个数字：
25 分钟的段配 30 分钟的提醒、45 分钟的段配 45 分钟的提醒，拆开会得到「一段跑 45 分钟、
中间被主题提醒打断两次」这种谁都不想要的组合。**提醒主题（themeCycle）不跟着走**——
那几句写的是这个模式的心法，和它跑多久无关。

装过旧版本的机器会**自动迁一次**，但**只认一个数都没改过的那一台**：五个数字全对得上才动，
自己调过就原样留着（改过就是有意的，和 0.6.x 那次路径迁移是同一条规矩）。迁完写下
`settingsVersion`，所以这件事一台机器上只发生一次——以后你有意把它调回旧的那一组，不会再被翻过去。

## 间歇节奏（0.9.0）

> 增加一个【切换】（开关开启后，自动切换 节奏和间歇）……比如 思考优先模式——第一次 45 分钟。第二次一半的分钟数。第三次、第四次，等等。（此处，为了简化 和长休息的轮数无关）

设置 → 番茄 → 模式 → 间歇节奏。开着的时候：

- **单数番茄**（第 1、3、5 个）跑基准时长，**双数番茄**（第 2、4、6 个）按倍数缩短（默认 50%）。
- **跟着的那一小段休息一起缩**——原话要的是「节奏**和间歇**」都换；只缩工作不缩休息，等于换成了另一种节奏。
- **长休息不缩**，也不看轮数：原话点名「和长休息的轮数无关」。那一段是给身体的，不是给节奏的。

以思考优先（25 + 5）为例：25 + 5 → 12.5 + 2.5 → 25 + 5 → 12.5 + 2.5 …… 改倍数只影响下一段，
正在跑的那一段不会中途变长变短。

## 新手 / 专家两档设置面（0.9.0）

> 【可配置项】实在是太多、太复杂了……建议你【增加 新手-开箱即用模式/专家模式】两种；默认是【新手-开箱即用模式】——大部分设置选项，是灰色的不许修改、仅查看；少部分设置，是可以手动修改的。

档位切换排在设置页最上面、**每一页都看得见**（新手模式下满屏都是灰的，切档的开关自己再躲起来，
人只会以为插件坏了）。划线的规矩写死成一句话：

> **新手模式下能改的只有两类——「这台电脑的显示偏好」和「这一层功能要不要」。所有参数、阈值、路径、凭据一律只读。**

所以新手模式下可改的就是这十七项：界面字号、当前模式、间歇节奏、重启之后接着上次、
启用悬浮提示、启用禅定模式、启用积分账本、启用目标树、启用候选区、启用睡前复盘、启用推动器、
静音、启用复工强提醒页、启用每日推荐、休息段锁屏、启用强制干扰、启用运行时音乐。

为什么是这两类：换一台电脑就要重调的东西（字号）不给改等于不能用；而每一层的总开关是**反悔口子**——
一个会锁屏、会闪屏的插件，人必须随时关得掉它，哪怕他还没搞懂下面那二十个参数。

**只读，不隐藏**（原话「灰色的不许修改、仅查看」）：藏起来的话，人连「原来这个东西可以调」都不知道。
实现上，每一项在**建的时候**标记号（`openInBeginner`），没标的一律锁上——所以新增一项的默认结果是
「改不了」，不会变成「悄悄能改」。切回新手模式**不会**还原你在专家模式下改过的值，只是把它们锁上。

`sessions[].goalId` 是 R3 加的：这个番茄在推进哪个目标树节点（`g-7`），没挂就是 `null`。旧日档没有这一位，下次落盘时补成 `null` 再写——**缺 key 和 `null` 是两份不同的字节**，不补的话每次写盘都会抖。

顶层 `points` 与 `sessions[].points` / `sessions[].pointsRule` 就是积分账本的位置。上面这份是账本还没动过的样子（一律 `null`）；开了「把当日积分写进番茄流水日档」之后，这三处会被填上当日快照——**它是派生数据，源头永远是账本 Markdown**，每次写盘整体重算，不会和源头漂移。

写盘走 RefBake 那套 `writeIfChanged`：序列化结果和磁盘上一模一样就不写，免得给 Easy-Git 刷空 commit。key 顺序在 `serializeDayLedger` 里手写死，也没有 `generatedAt` 之类每次都变的字段。

## 积分账本

出处是《知识库》第 128 行那一句——「将完成任务做成积分制、而享乐就要消耗积分」。

### 为什么是账本，不是计数器

计数器只回答「现在多少分」。账本要回答「这周的分是怎么来的、怎么没的」——这是睡前复盘唯一能吃的输入。
所以每一笔都带 时间 / 账本日 / 方向 / 分值 / 事由 / 来源 / 任务 / 关联，可回溯、可审计、可撤销。

### 为什么落 Markdown 而不是 JSON

**番茄流水是机器遥测，积分账本是给人看的账。** 两者故意不用同一种格式：

- 流水是秒级的、只给插件自己读，JSON 最省事；
- 账本是要在 Obsidian 里**直接翻、直接搜、必要时直接改**的东西。Markdown 表格在 Obsidian 里渲染成表格，JSON 只是一坨纯文本。
- frontmatter 里的 `earned` / `spent` / `closingBalance` 会变成 Obsidian 的属性，Dataview 直接能查。
- 一个月一份、按时间追加，git diff 基本只在末尾长，Easy-Git 那边看着干净。

代价是解析要容错。所以：**读不动的行不会被丢掉**，会原样搬到文末《待修复》，改好了下次读盘自动归位（`test/points.test.js` 有来回不丢的用例）。

### 账本长什么样

落在设置里的「账本目录」下，一个月一个 `YYYY-MM.md`：

```markdown
---
schemaVersion: 1
month: 2026-08
generator: life-cockpit@0.2.0
openingBalance: 0
earned: 12
spent: 12
closingBalance: 0
entryCount: 3
---

# 积分账本 2026-08

## 流水

| 时间 | 账本日 | 方向 | 分值 | 余额 | 事由 | 任务 | 来源 | 关联 | 状态 | ID |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 2026-08-09 09:25 | 2026-08-09 | + | 2 | 2 | 完成番茄：完成一个番茄 · 写 PRD | pomodoro | 番茄 | work-1-1754697600000 | 有效 | 20260809-0925-k3f1a2 |
| 2026-08-09 21:00 | 2026-08-09 | - | 12 | -10 | 刷视频 30 分钟 | video | 手动 | - | 已撤销 | 20260809-2100-9dz0qq |
| 2026-08-09 21:05 | 2026-08-09 | + | 12 | 2 | 撤销：刷视频 30 分钟（其实没刷） | video | 撤销 | 20260809-2100-9dz0qq | 撤销 | 20260809-2105-b71xkc |
```

- **余额**一列是算出来的（全账累计，跨月连得上），改它没有意义。
- **状态**一列也是算出来的，读盘时忽略。
- 事由里的 `|` 会转义，不会把表格切坏。
- 写盘走和 RefBake 一样的 `writeIfChanged`：同样的账序列化出同样的字节，内容没变不落笔。

### 撤销

记错的一笔按「撤销」→ 写一笔**方向相反、`来源=撤销`、`关联` 指回原笔**的新流水，原笔照旧留在账上，**不做静默删除**。

- 余额会走过去、再走回来，账面留下痕迹；
- 汇总时原笔和撤销单都不计入入账 / 出账（两者相抵为零），所以「这周花了多少分」不会被撤销污染；
- 同一笔不能撤两次，撤销单本身也不能再撤。

### 任务与分值在哪儿维护

在 vault 里的一篇笔记（默认 `LifeCockpit/积分账本/积分任务表.md`），不是在设置页里——任务清单会长，改在笔记里顺手得多。
命令面板跑一次 `写出积分任务表` 会写出一份默认表（取自日记模板《今日每日任务》的六维与早晚流程），之后直接改：

```markdown
| ID | 名称 | 方向 | 分值 | 分类 | 启用 |
| --- | --- | --- | --- | --- | --- |
| pomodoro | 完成一个番茄 | 入账 | 2 | 诚 | 是 |
| video | 刷视频 30 分钟 | 出账 | 12 | 享乐 | 是 |
```

`ID` 用过就别改（账本按它指回来）。改完在设置里按「重读」，或跑 `重读积分账本`。

**临时任务不用先登记**：记账窗里选「临时任务」，自己填分值和事由即可——「非周期性 / 非常规 / 临时任务」本来就是当场才知道的。

### 番茄怎么自动入账

跑满一个工作段就按面板上挑的那个预设任务入一笔（没挑就走设置里的默认项）。

- **跑满才算**，手动结束或跳过不计分；
- 同一个番茄段只入一次账（`关联` 认的是番茄段 id，重放不会重复计分）；
- 面板上万一挑到享乐项，会退回默认任务——番茄不该倒扣分。

### 给睡前复盘（R5）留的口子

复盘要问的是「今天挣了多少、花了多少、净剩多少、都花在哪、哪笔不该花」。所以：

- `summarize(book, from, to)` 一次给出 期初 / 入账 / 出账 / 净额 / 期末 / 按任务分组 / 按天切片；
- 开了「把当日积分写进番茄流水日档」之后，当天的 `YYYY-MM-DD.json` 里同时有番茄流水和积分流水，**复盘打开一个文件就够**，不用自己拼两套存储。

## 目标树

出处是《知识库》「全目标管理」那六层：

```
宇宙级目标 → 人生级目标 → 大阶段 / 五年计划级 → 【年度】OKR → 【季度到每周】KPI → 日内目标（项目规划 / Goal / Spec / Issue）
```

### 重点是回灌，不是拆分

只做单向拆分，等于又造了一堆静态清单——那种东西已经有很多了。所以这棵树里**进度默认是算出来的**：叶子给数，上层按权重收。勾掉一个日内目标，能当场看见 KPI、OKR 一路到宇宙级的条子都往前动一格。

取值顺序（写在 `computeProgress` 里，全树唯一的真相）：

1. **已放弃** → 0，并且**整支退出上层汇总**——放弃一个子目标不该让父目标永远背着；
2. **已完成** → 100，压过子节点（人手动结项，这是他自己的人生）；
3. **有未放弃的子节点** → 子节点进度按 `权重` 加权平均，**这一条就是回灌**；
4. **有度量** → `current / target`（数据比估计可信，压过手写完成度）；
5. **有手写完成度** → 用它；
6. 都没有 → 0。

### 向下拆分是半自动的

拆分窗只**出建议**，改完、勾完、按了「落到树上」才写盘。父目标有度量的话，量会摊到每一段（整数摊整数，余数给靠前的几段），并且**摊到的量直接当权重**——所以一段做完，父目标涨的正好是这一段占的比例，拆分和回灌对得上账：12 章拆成 4 个季度，做完 Q1 就是 25%；10 篇拆成 4 段是 `3/3/2/2`，做完第一段是 30%。

切法有按季度 / 按月 / 按周 / 按天 / 均分成若干段，段名分别是 `2026 Q1`、`2026-01`、`2026-W03`、`2026-08-11`、`第 1 段`。子目标的截止不会越过父目标的截止。

### 树长什么样

整棵树落成一篇 Markdown（默认 `LifeCockpit/目标树.md`）。选缩进列表而不是表格，理由很简单：**树的形状要看得见**。

```markdown
---
schemaVersion: 1
generator: life-cockpit@0.3.0
nextId: 13
nodeCount: 10
doneCount: 1
progress: 12.5
---

## 树

- [ ] 宇宙级目标：我愿意为之存在的那个尺度 [进度:: 12.5%] ^g-1
    - [ ] 人生级目标：这一生要成为什么样的人 [进度:: 12.5%] ^g-2
        - [ ] 大阶段 / 五年计划：未来五年最该完成的那件事 [进度:: 12.5%] ^g-3
            - [ ] 【年度】OKR：写完第二版 [进度:: 12.5%] [度量:: 0/12 章] ^g-4
                - [ ] 写完第二版 · 2026 Q1 [进度:: 50%] [度量:: 0/3 章] [权重:: 3] [截止:: 2026-03-31] ^g-7
                    - [x] 写第 1 章 [进度:: 100%] [类型:: Spec] ^g-11
                    - [ ] 写第 2 章 [进度:: 0%] [类型:: Spec] ^g-12
```

- **缩进决定层级**：顶格是宇宙级，每往里缩一层降一级，最深停在日内目标。跳级（人生级底下直接挂 OKR）会写出 `[层级:: OKR]`；tab 和空格混用也排得出父子。
- **记号只认四个**：`[ ]` 未开始、`[/]` 进行中、`[x]` 已完成、`[-]` 已放弃。别的记号会被归一成未开始。
- **`[进度:: n%]` 是算出来的**，和账本里的「余额」一列同一套规矩：写盘写出来给人看，读盘直接扔，改它没有意义。
- 行内字段是 Dataview 认得的 `[key:: value]`；**不认识的字段原样带着走**，不替人删。
- **行尾的 `^g-7` 是节点 id，同时是 Obsidian 的块引用锚点**：`[[目标树#^g-7]]` 能直接链过来。编号只增不减——删掉 `g-7` 之后新建的是 `g-8`，免得旧账指到一个毫不相干的新目标上。
- 手写一行没写 `^id`？读盘时自动补号。同一份文件读两遍补出来的号一样。
- 认不出来的行搬到文末《待修复》，**不删**；在那儿改好了下次读盘自动归位。

写盘走和 RefBake 一样的 `writeIfChanged`：同样的树序列化出同样的字节，内容没变不落笔。

### 和番茄打通

驾驶舱面板顶上多了一个「推进的目标」下拉（也可以在目标树里点 ○，或者跑命令 `把番茄挂到某个目标上`）。挂上之后：

- 番茄流水那条 session 的 `goalId` 记住它，**这个番茄是在推进哪个目标**；
- 禅定遮罩的副标题写着「推进「XXX」」；
- 面板下面一行摊开整条路径 `人生 › OKR › KPI › 日内` 和回灌上来的进度，外加今天已经往这一支投了几个番茄。

能挂的只有**没完成的日内目标与 KPI**——OKR 太高，挂上去没有意义。挂着的那个目标被删了或做完了，选择会自动放掉。

### 和积分账本打通

挂了目标的那一笔积分，账本里的「任务」一栏写成 `goal:g-7` 指回目标树节点。**这里没有另起字段**：`PointsEntry.taskId` 本来就是「这一笔挂在哪一项上」，现在两个命名空间共用它——裸 id 是积分任务表里的预设任务，`goal:` 开头的是目标树节点，`null` 还是临时任务。

一个位只能写一个，所以挂了目标就按目标记：**复盘要问的是「分都花在哪个目标上」**，计分规则本身照旧写在事由里（`完成番茄：完成一个番茄 · 写 PRD`）。不想这样就在设置里关掉「按目标记账」，账本回到按计分规则记，目标只留在番茄流水的 `goalId` 上。

账本窗的「分去处」会把 `goal:` 解析成整条路径；目标被删了也如实写「已不在树上」，不把这几笔悄悄并进临时任务。

## 夜班候选区与拍板面

**人机交班面。** 分工是定死的：Obsidian 是人在时的前台，Multica 是人不在时 Agent 自己发挥的场。缺的一直是两者之间的交接口——这一节就是它。

> 夜班产物默认落到候选区，不直接改主干。

**有收口面，才敢放绿灯。** 产物进不了主干，夜里最坏的结果也只是拍板面上多几行待办。

### 候选区长什么样

落盘格式不是本插件定的，是和 `tools/news-inbox`（资讯夜班）**共用的一份约定**，原文在 [`docs/资讯_投喂口_收件箱_候选区/资讯收件箱与候选区-约定.md`](../../../docs/资讯_投喂口_收件箱_候选区/资讯收件箱与候选区-约定.md)。插件直接实现那份文档，没有另起一套。


**`一句话说明` 就是拍板面上那一行**，所以约定要求它只有一行。`目标落点` 允许为空串——表示这条只给人看，没有落点。连 frontmatter 都没有的裸 `.md` 扔进当天目录也认，缺的字段当空处理：**约定定得复杂，夜班就没人遵守。**

### 三个动作

侧栏「夜班候选区」（ribbon 的收件箱图标，或命令 `打开夜班候选区`）列出全部待拍板项，每条三个按钮：

| 动作 | 做了什么 | 原件去哪 |
| --- | --- | --- |
| **采纳** | 按 `类型` 分派落点，写进主干，主干那边留一行指回原件 | 带着裁决移进 `_归档/<日期>/`，**不删** |
| **打回** | 写一句理由进 `裁决` | **留在原地**——下一轮夜班扫的就是它 |
| **改写** | 新正文写回本文件，原正文追加到文末《原始产物》 | 留在原地，等你再采纳或打回 |

三个动作全部**追加**到 `裁决` 数组，历史不覆盖：谁、什么时候、拍了什么板、落到哪儿，全在文件里。

**打回的理由是写给下一轮 Agent 的**，所以打回的文件不归档——夜班跑之前先扫一遍最近的打回理由。拍板面顶上也会把最近三条理由列出来，省得你忘了自己上次说过什么。

**改写不是终局。** `已改写` 的条目照旧留在待拍板列表里，改完还得采纳或打回。反复改写会在《原始产物》下面一块块累加，每块带改写时间，上一版不会被冲掉。

### 采纳落到哪儿：按类型分派

`类型` 是分派开关。落点填错是常事，所以采纳窗里的落点**可以当场改**——改一下就能落，比打回一轮快。

| 类型 | 落到哪儿 | `目标落点` 是什么 |
| --- | --- | --- |
| `news-digest` / `note` / 没写 | 正文追加进落点笔记，前面带一行溯源 | vault 内笔记路径；已有内容是**追加不是覆盖** |
| `goal-node` | 目标树（R3）多一个节点 | 挂在哪个节点下（`g-7` / `goal:g-7` / `[[目标树#^g-7]]`），留空挂顶层 |
| `ledger-entry` | 积分账本（R2）多一笔 | 这一笔记在哪个目标节点上，留空按 `任务` 记 |

- **落点笔记里认得出重复**：同一条采纳两次不会写出两份。
- **`ledger-entry` 缺 `方向` 或 `分值` 直接拒绝**，原件一动不动——账目宁可不落，也不猜。
- **落点写失败就整条中止**，候选项不动、不归档，人还能再按一次。

### 不丢

这一整块的规矩只有一条：**不静默丢东西。**

- 采纳的原件移进 `_归档/`，不删；归档里已经有同名的就退一位（`-2`、`-3`），不覆盖。
- 打回和改写都不动原始产物：打回连正文都不碰，改写把原正文留在文末。
- 约定之外的 frontmatter 键**原样带着走**，插件不替夜班删。
- 拍板动作全程可回溯：`裁决` 里有人、有时间、有落点、有理由，主干那边有指回归档原件的链接。

写盘照旧走 `writeIfChanged`；读进来再写回去和夜班写的**一个字节都不差**，不给 Easy-Git 刷空 commit。

## 睡前复盘

出处是《知识库》第 144 行那一句——「每天睡觉之前检查计划、复盘（**AI 为主，人工为辅**），是否已经达到满意的完成程度」。

这是整个驾驶舱的最后一环：前四轴各自往 vault 里写东西，这一环把它们收回来，**并且让系统自己长记性**——「不贰过」从手写变成自动进账，走的就是这条路。

### 一轮复盘做什么

到点（默认 22:00，对齐节律表里睡觉段的起点）弹一条提醒；也可以随时手动发起——命令 `睡前复盘`、候选区面板顶上的「睡前复盘」按钮、设置页里的「现在复盘」，三个入口跑的是同一条：

```
取数（R1 番茄 + R2 积分 + R3 目标树 + 上一轮的打回理由）
  → 落一份素材包 JSON
  → 出一版复盘草稿
  → 投进 R4 的候选区
  → 你在拍板面上采纳 / 打回 / 改写
  → 采纳的那一刻才回写日记 / 目标树 / 错题本
```

**复盘自己一个字都不往主干写。** 写主干是采纳那一下的事，也就是你按下按钮的那一刻。

### 取数：一份素材包，不用自己翻三处

落在设置里的「复盘素材目录」下，一天一份 `YYYY-MM-DD.json`：

```json
{
  "schemaVersion": 1,
  "day": "2026-08-09",
  "generator": "life-cockpit@0.5.0",
  "focus": {
    "minutes": 60, "targetMinutes": 560, "ratio": 10.71,
    "completed": 2, "started": 3, "breakMinutes": 5, "onGoal": 2,
    "byTask": [{ "task": "写 PRD", "minutes": 50, "completed": 2 }]
  },
  "points": {
    "opening": 0, "earned": 6, "spent": 12, "net": -6, "closing": -6,
    "count": 2, "voidedCount": 0,
    "byTask": [{ "key": "goal:g-6", "label": "宇宙级目标 › … › 日内目标", "earned": 6, "spent": 0, "count": 1 }]
  },
  "goals": {
    "overall": 0,
    "touched": [{ "id": "g-6", "title": "日内目标：今天要推进的那一步", "progress": 0, "pomodoros": 2, "earned": 6, "spent": 0 }]
  },
  "rejections": [{ "at": "2026-08-08T22:30:00+09:00", "reason": "完成度判断太宽了", "from": "睡前复盘-复盘正文.md" }],
  "dimensions": ["诚 · 精诚所至，金石为开", "…"]
}
```

- **目标树那一栏只列今天真动过的那几支**（投过番茄的、记过分的）。整棵树列出来等于没汇总——复盘要问的是「今天推进了哪一支」，不是「树上有什么」。挂着的目标被删了也如实列成「已不在树上」，不把那几个番茄悄悄丢掉。
- **`rejections` 是上一轮复盘被打回的理由。** R4 打回时不归档、文件留在原地，所以下一轮扫一遍候选区就能读回来——**别在同一个地方栽第二次**。只认复盘自己投出去的那几条，别人的打回理由跟这一轮没关系。
- 写盘走 `writeIfChanged`，key 顺序手写死，没有 `generatedAt` 之类每次都变的字段：同一天重跑不落笔。

### 素材包什么时候写出来（0.10.0 改了）

**0.9.0 及以前：只有你手动发起复盘那一刻才写。** 于是链条的第一环挂在「今晚记不记得点一下」上——
夜班 23:30 来读的时候文件不在，那一晚就整条空跑。真实发生过好几天，报的就是那句
`没有素材包：驾驶舱运行区/复盘素材/2026-08-17.json 不存在`。

**0.10.0 起：睡前提醒那一刻自动落一份**（设置 → 交班 · 复盘 → 睡前复盘 → 「到点自动落一份素材包」，默认开）。
它**只写这一个 JSON**——不出草稿、不投候选区。那两件事一件是判断、一件是交班，仍然由人（或夜班）发起。

三条路都能得到同一份素材包，字节完全一样（`writeIfChanged`，没变不落笔）：

| 怎么来的 | 做了什么 |
| --- | --- |
| 到点自动 | 取数 → 写素材包 |
| 命令面板 `只生成复盘素材包` | 同上，随时补一次 |
| 命令面板 `睡前复盘` | 取数 → 写素材包 → 出草稿 → 投候选区 |

> Obsidian 得开着才写得出来。夜班在别的机器上跑，它读的是仓库里那个文件——所以
> 睡前那会儿 Obsidian 关掉了的话，仍然会没有素材包。

### AI 接在哪一段

接口有**两种接法，同一个形状**：

1. **插件自己问模型**（0.10.0 新增）——设置 → 交班 · 复盘 → AI 接口里配一档，睡前复盘当场出草稿；
2. **外面的 Agent 出**——读素材包 JSON，交回一份 `ReviewDraft`。夜班 autopilot 走这条。

**素材包进去，一份 `ReviewDraft` 出来。** 这就是接口的全部：

```json
{
  "day": "2026-08-09",
  "author": "agent:夜班复盘",
  "body": "## 睡前复盘 · 2026-08-09\n\n### 完成度判断\n……",
  "plans":    [{ "title": "把第二节写完", "parent": "goal:g-5", "level": "日内目标", "kind": "Spec", "due": "2026-08-10", "note": "……" }],
  "mistakes": [{ "title": "晚上八点之后开新任务", "harm": "大半天", "odds": "中等", "cause": "……", "lesson": "晚上只收尾，不开新题" }]
}
```

换模型、换渠道都不动这条链路上的任何一行——取数和回写做扎实，AI 那一段留干净。夜班 autopilot 的接法见 [`docs/资讯_投喂口_收件箱_候选区/资讯投喂口-夜班接线.md`](../../../docs/资讯_投喂口_收件箱_候选区/资讯投喂口-夜班接线.md) 的《睡前复盘那一班》。

**没有模型也能跑。** 内置的是一版**兜底草稿**，和 `tools/news-inbox` 的抽取式兜底同一个定位：确定性、不需要模型、**不产生洞见**。

- 算得出来的都算出来：完成度判断（专注 x/560、跑满几个、账是正是负、整树进度）、偏差在哪（离目标差多少分钟、几个番茄没跑满、几个没挂目标、有没有超支）。
- 判断得出来的一律留空：「明天该改什么」只留位置不填，`plans` 和 `mistakes` 一律是空数组。**不是每天都有不贰过级别的教训，宁可少记，不要把错题本灌成流水账。**

**模型跑不通就退回兜底，但绝不静默。** 缺密钥、HTTP 401、返回空正文、JSON 读不出来——
四种都会当场弹一句说清楚是哪一种，然后用兜底草稿。夜里静默降级比直接失败更难发现：
第二天看到的是一份「看起来正常但没有洞见」的复盘，没人会去查模型是不是根本没跑。

### AI 接口怎么配（0.10.0；0.11.0 挪成全局）

设置 → **AI 接口**（自己一页）。默认**关**——它要花钱、要密钥，这两样都该由你明确点头。

> **0.11.0 起它不再挂在「交班 · 复盘」下面。** 原话是：
>
> > 「现在的【DeepSeek Flash】AI 的 API 接口，仅仅在【复盘】这里放了配置——其实，将来，
> >  它会变成一个【全局性】的设置——因为其它地方，可能也大量使用到 Flash AI 接口。」
>
> 一层被好几处共用的东西藏在其中一处底下，第二处接进来的那天就必然要搬家。所以现在
> 档位表和密钥在自己一页上，页里有一张**「谁在用它」**——加一处用途 = 那张表里加一行
> （`AI_CONSUMERS`），配置本身一个字不用动。今天表上只有一行：睡前复盘草稿。

一档就是一行配置，加一个模型 = 加一档，不用改代码：

| 字段 | 说明 |
| --- | --- |
| base URL | OpenAI 兼容地址，**末尾不带** `/chat/completions`（带了也认，会兜住） |
| 模型 | 填端点自己认的那个 id |
| 密钥 | 存 vault 内的 `data.json`（`.obsidian/plugins/life-cockpit/data.json`，**不在 2A-META 仓库内**，不随仓库公开） |
| 密钥环境变量名 | 上面留空时读它。两处都空 = 缺配置，插件停下来说缺什么，**不猜、不写死** |
| 超时 / max_tokens | 下限 5 秒；`max_tokens` 预置 **32768**，见下面那条警告 |

> **`max_tokens` 别调小。** 这两档都是推理模型：它先吐一大段 `reasoning`，而那一段
> **同样吃 `max_tokens` 的额度**。2026-08-18 拿真实的复盘 prompt 连跑了几轮：
> 4096 直接拿到 `finish_reason: length` + **正文完全为空**（一次「成功」的 HTTP 200，里面什么都没有）；
> 16384 大多数时候够，但**踩到过一次全额吃光**。实测 completion tokens 在 1921–7862 之间跳。
> 所以预置值是按最差的那一次留余量给的。真踩到时插件会把这句话直接说给你听，重跑一次通常就好——
> reasoning 那一段的长度每次都不一样。

预置两档，**都不带密钥**：`OpenCode Go · DeepSeek v4 Flash`（`deepseek-v4-flash`）和 `… Pro`（`deepseek-v4-pro`），
地址都是 `https://opencode.ai/zen/go/v1`。

> **模型 id 以端点自报的为准。** 2026-08-18 问过 `GET /v1/models`：那上面只有 `deepseek-v4-flash`，
> 没有 `deepseek-v4-0731-flash`。照人话去猜 id 会得到一个 404。

配完按一下【测一次连接】，通没通当场看得见，不用等到睡前那一刻才发现没配对。

### 每一次调用都留痕（0.11.0）

> 「目前 Flash 的执行——其实我看不到【请求和返回】，这样，如果出现了错误或者偏离；
>  我是意识不到的？（可能，需要存储 N 天之内的记录，在本地；然后插件设置里，
>  有一个开关，可以简单列表式的预览一下。）」

设置 → AI 接口 → **调用记录**。默认**开**：一层看不见请求和返回的 AI，出了偏差没人会发现。

- **记什么**：时间、哪一档、模型、谁要它跑的、地址、HTTP 状态、耗时、token 用量，
  以及**发出去的完整 prompt 和收回来的正文**。
- **失败的也记**——而且最该记。缺密钥根本没发出去、HTTP 401、返回空正文，这三种在列表里
  是三条不同的记录，各自带着自己的那句原因。
- **密钥一个字符都不进日志。** `Authorization` 是整条摘掉，不是打码：打过码的密钥仍然会
  连着前缀进截图、进备份。`test/ai-log.test.js` 有一条专门守着这件事。
- **落在哪儿**：`.obsidian/plugins/life-cockpit/ai-log/YYYY-MM-DD.json`，和 `data.json` 同级，
  **不在 2A-META 仓库内**。请求正文里带着当天的番茄、目标和飞书条目，那是私事，
  写进公开仓库等于把它公开出去。
- **留几天**：默认 7 天，一天一份文件，过期整份删（载入时清一次）。一天最多 200 条，超了丢最老的。

设置页上直接列最近 5 条；点【看全部】开详情窗，一行一条、点开看正文，请求和返回都能一键复制。
命令面板里也有一条【看 AI 调用记录】。

### 落盘：复盘进当日日记，六维和日记模板对得上

复盘正文的落点是「日记目录」下的当日日记（默认 `LifeCockpit/复盘日记/YYYY-MM-DD.md`），采纳时是**追加**，你自己先写的那段一个字不动。

正文里的《六维回看》按 诚 / 爱 / 当 / 意 / 诚 / 体 排，措辞取自日记模板《今日每日任务》的原句（`SIX_DIMENSIONS`）——**不另起一套维度**，复盘落进日记之后和上面那份任务清单对得上。

### 回写：三个去处，全走 R4 已有的处理器

| 复盘产出 | 候选项类型 | 落点 |
| --- | --- | --- |
| 复盘正文 | `note` | 当日日记，追加不覆盖 |
| 明日计划（每条一份） | `goal-node` | 挂在哪个目标树节点下，采纳后树上长出节点，落点写成 `[[目标树#^g-7]]` |
| 不贰过（每条一份） | `note` | 错题本笔记，追加不覆盖；**同一条采纳两次不会写出两份** |

**没有 `ledger-entry`。** 复盘不替人记账：分该怎么记是当场的事，隔一天由复盘补记只会让账目和事实对不上——账目宁可不落，也不猜。「不贰过」那一条写成错题本里已有的形状（`（危害时长：… 发生概率：…）` 打头，底下挂直接原因和反省），不另起一套格式。

### 重跑安全

复盘会被反复发起（到点一次、手动几次、夜班再来一次），所以重跑必须无害：

- 同一天重投写出同样的字节，`writeIfChanged` 不落笔；
- **你已经拍过板的那几条一律跳过**，报出来但不覆盖——夜班可以放绿灯，绿灯不包括抹掉你的决定；
- **采纳过的不会被复活。** 原件已经躺在 `_归档/` 里，重跑不会在原地再刷一条待办出来。

## 飞书金字塔表格（0.10.0）

仓库主人每天的具体任务写在飞书那张金字塔表格上，**这一层不打算把那张表搬进 Obsidian**：

> 「飞书的金字塔表格，是一个非常适合我的表格；然后目前，我感觉 ta 很够用，
>  **还不用完全重写内置到 Obsidian 里面**（而是我仍然在飞书表格上面做记录）。」

所以插件做的是四件事：**给一个点得开的入口**、**读一份别人导出好的快照**、
通过 Convex job **按一下更新飞书【总结】页**，以及保留一条旧的快照补充链（见下面《快照是怎么来的》）。

### 为什么是快照，不是直连飞书 API

导出那条路**已经有一条跑通的管线**了（`lark-cli sheets +export` → xlsx → `all_tasks.json`，
靠单元格填色判完成度）。那条管线拿着 user token、认得那张表的版式；插件再写一遍只会得到一个
更差的第二实现，而且要把飞书凭据搬进 vault。**约定的输入就是那条管线已经在产的
`all_tasks.json`**——拷进快照目录即可，格式一个字节都不用改。

### 快照放哪儿、长什么样

设置 → 交班 · 复盘 → **飞书金字塔表格**。默认快照目录
`LifeCockpit/飞书快照/`，一天一份 `YYYY-MM-DD.json`。

找文件的顺序是 **今天 → `latest.json` → 目录里最新的那一份**。第三条是关键：快照是隔几天才更新一次的东西，
只认当天文件的话这一栏一年里有大半年是空的——而它要回答的「我最近都在做什么」恰恰不要求当天。
读到的不是今天那一份时，面板和复盘正文里都会把「这是表上最近有记录的一天」写出来。

三种形状都认（约定定得复杂就没人遵守）：

```jsonc
{ "generated_at": "…", "all_tasks": [ … ] }   // 导出管线的原始产物，直接拷
{ "tasks": [ … ] }                              // 别的脚本产的
[ … ]                                           // 最省事的写法
```

每一条只用得上五个字段，其余原样忽略：

```json
{ "sheet": "2026年07月02日 周四", "text": "看完一整本书吧？",
  "status": "完全没去做", "difficulty": "中难", "side": "个人兴趣" }
```

- 日期从 `sheet` 名解（`2026年07月02日 周四` → `2026-07-02`，尾巴上的 `周四` / `3^` 一律不管）。
  模板页解不出日期，那**不是错误**——它只是不算进任何一天。
- `status` 认四种：`已完成` / `完成了一部分` / `完全没去做` / `未知状态`。认不出来的一律落到「未知状态」，
  **不假装已完成**。

### 快照是怎么来的（0.11.0）

> 「飞书的这里，你说有【快照目录】——（其实我没看到有生成，也并不明白 相关的工作机制是怎样的？）」

**照实说：0.10.0 只写了「读」的那一半。** 现在的主路径由 Convex 编排：插件提交
`feishu:requestPull`，有 lark-cli 的自动化运行 `refresh_feishu_summary.sh`，把最新快照
推入 Convex 后再写回【总结】页。旧版不依赖 Convex 的 webhook + Easy-Git 链仍可手动补快照，
但它不再是更新总结页的主入口。

整条链，五步：

| 步 | 谁干的 | 干什么 |
| --- | --- | --- |
| ① | 你 | 按【更新总结页】（驾驶舱面板 / 数据台 / 命令面板 / 设置页都有） |
| ② | 插件 | 调 Convex 的 `feishu:requestPull`，订阅 `jobs:watch` |
| ③ | Convex + 自动化 | 派 Mac 上的 `refresh_feishu_summary.sh`：导表、推快照、写【总结】页 |
| ④ | 插件 | 面板显示 job 的进度和最终成功 / 失败；Convex 回执更新数据台 |
| ⑤ | 备用链 | Convex 不可用时才用旧 webhook + Easy-Git 拉回快照，再按【重读快照】 |

主链的完成状态由 job 回执回答；备用链的完成状态仍然不问 webhook，而是看快照产物本身。

> 「又因为 WebHook 可能不太好获得，具体的一个完成状态——」

对，webhook 返回 2xx 只说明「这一嗓子喊出去了」。所以这里根本不问对面要状态：
**产物本身就是状态**。触发那一刻先记下盘上那份快照的身份（日期 + 导出时间 + 条数，
**不看文件 mtime**——Easy Git 拉一次 mtime 就变，那个信号是废的），之后每 30 秒
跑一次拉取命令、看一眼快照；身份变了就是「到了」，并且报出用了多少秒。

等不到**不算失败**，只是「还没等到」：对面可能跑了十分钟，也可能今天就没人在。
这两种都不该看到一句红色的「失败」——那会让人去查一个根本没坏的东西。

配置在 设置 → 交班 · 复盘 → 飞书金字塔表格：

| 字段 | 说明 |
| --- | --- |
| 更新总结页 | Convex 同步 → `feishu:requestPull`；需要服务地址和设备令牌 |
| 备用：拉取快照的 webhook | Multica 上旧自动化的地址；留空则读 `LIFE_COCKPIT_FEISHU_PULL_WEBHOOK`。两处都空 = 没有这条补充路，插件**不编造地址** |
| 等新快照的命令 | 默认 `easy-git:sync-all`。**复用 Easy Git 已配好的 GitHub 凭据——调命令，不抄密钥**，所以插件自己一个 token 都不存。留空 = 拉仓库这一步你自己来 |
| 最多等几秒 | 默认 180。下限 10——比拉一次仓库还短的等待只会次次「没等到」 |

### 和目标树、目标项结合（0.11.0）

> 「1、仍然需要，和【目标树、目标项】，做一个结合。」

结合点是**关键词**，不是 id：那张表是你在飞书上手写的，上面没有、也不该有目标树的节点号。
要求你在飞书里写 `g-7` 等于把两个系统焊死，而你明说了「我仍然在飞书表格上面做记录」——
所以对齐这件事由插件这一侧承担。

目标树面板 → 编辑某个目标 → **飞书关键词**（顿号 / 逗号 / 空格分隔，可写多个）。
落盘写成 `[飞书:: 量化、赛马]`，你也可以直接在目标树笔记里手写。表上正文含其中任意一个的条目，
就算在这支目标名下。**一条同时命中两支目标就两边都算**——一件事推进两支目标是常态，
强行判给其中一支只会让另一支看起来没动。

配好之后：

- **目标树面板**上每支目标后面多一枚徽章 `飞书 2/3`（表上挂在它名下的条目，成了几条）；
- **复工强提醒页**上多一段《飞书 × 目标树》，按目标分组列没做完的那几条，
  **挂不上任何目标的单列一栏**——这一栏问的就是「今天做的事到底在不在目标上」。

关掉这一层用 设置 → 飞书金字塔表格 → 【按目标树分组】。

### 它出现在三个地方

| 在哪儿 | 显示什么 |
| --- | --- |
| 复工强提醒页 | 当天表上的条目，**没做完的排前面**——被拦下来的那几秒该看的是「还欠什么」 |
| 驾驶舱面板 / 数据台 | 【更新总结页】主按钮、job 进度、回执 + 【打开表格】【重读快照】；旧快照按钮标为备用 |
| 复盘素材包 | `feishu` 那一栏：计数 + **已完成 / 没做完的原句** |

原句进素材包是有意的：番茄流水记的是**时间去处**，飞书表格记的是**事情本身**。
「我每天都大概干了什么、我是一个什么方向的人」这一问，只有原句答得了，计数答不了。

没有快照的那一天，素材包里**连 `feishu` 这个键都不写**——多写一个恒定的 `null`
会让所有旧素材包在升级当天集体重写一遍，给 Easy-Git 刷一串空 diff。

## 一天从几点开始

14 小时工作制会跨零点，所以「当日」不等于自然日。默认凌晨 4 点换天：01:30 收工的番茄记在前一天。设置里可改。

## 五行列怎么对应日期

原表只写了 `金一 木二 水三 火四 土五` 五列，没说哪天是哪列。插件给了两种映射，设置里切：

- **周一到周五**（默认）—— 一二三四五 = 周一到周五，周末没有对应列。
- **五天一轮** —— 从锚点日起五天一轮，不管星期。

两种都有测试。**默认值是推断的，不是原表写死的**——如果本意是另一种，改设置即可，不用改代码。

时段沿用原表：早起 05-09、三小时工作日 09-12、双数日 13-17、单数日 18-22、睡觉 22-05（跨零点）。**12-13 和 17-18 原表就是空的，这里也保持空档**，不替表主人补格子。

## 推动器

前五样造的都是**内部**：时间、状态、结构、交班、收口。它们有个共同前提——人得先坐下来看一眼。
推动器造的是**外界**。出处是仓库主人自己的话：

> 「老板叫回去开会」的「清醒行动迅速」其实是【外界推着你走】

### 五道闸

推动器最容易死在两件事上：**推不动人的推送等于噪音，推太多会被整个关掉**。
所以每一条消息在发出去之前要过五道闸，任何一道拦下来都**明确记下理由**——「今天怎么没推」答得出来：

| 闸 | 管什么 | 「强制」级豁免吗 |
| --- | --- | --- |
| 全局静音 | 人明确要求安静 | **不豁免**。静音是指令，不是建议 |
| 分级阈值 | 提示 / 推一把 / 强制，低于阈值不推 | 本身就是分级 |
| 免打扰时段 | 默认 22:00–05:00，对齐节律表的睡觉段 | 默认豁免，可关 |
| 同键冷却 | 同一件事默认 10 分钟内不重复 | **不豁免**。同一件事炸十遍比不推更糟 |
| 每日配额 | 默认 24 条 | 豁免。强制级靠冷却限，不靠配额 |

嫌吵的正确顺序是：**先往上调分级阈值 → 再调配额 → 最后才是整个关掉**。

### 渠道

渠道是接口（`PushChannel`），谁实现都行。现在有三条：

| 渠道 | 要凭据吗 | 状态 |
| --- | --- | --- |
| 系统通知 | **不要** | 默认开。走系统级通知而不是 Obsidian 内的 Notice——人切到别处也看得见，而要推的恰恰是已经切走的那个人 |
| 飞书 | 要（webhook 地址，签名密钥可选） | 默认关。填了才用 |
| 通用 webhook | 要（一个地址） | 默认关。邮件网关、工单系统都从这里接 |

**凭据只有两处来源：设置项 → 环境变量。没有第三处，仓库里也不留任何真实地址或密钥。**

- 飞书：`LIFE_COCKPIT_FEISHU_WEBHOOK` / `LIFE_COCKPIT_FEISHU_SECRET`
- 通用 webhook：`LIFE_COCKPIT_WEBHOOK_URL`

两处都空 = **缺配置**，插件在设置页和驾驶舱面板上把缺的那一项名字写出来，不猜、不写死、不静默降级。
写进设置项就等于写进 vault 里的 `data.json`，自己掂量；不想写就用环境变量。

**粘进来的东西会先洗一遍（0.17.0）。** 密钥是整个配置里唯一必须由人手工搬运的东西，
而复制这条路上什么都会跟着来：末尾一个换行、`"apikey": "…"` 连键带引号、`Bearer ` 前缀、
多带的一个逗号、从网页上刮下来的零宽字符。它们一个都不属于密钥，却每一个都换来一个 401——
**而 401 和「key 填错了」长得一模一样**（AME-273 第 2 条）。所以：

- **自动去掉**：任意位置的空白（不只首尾）、成对的包裹引号、`apikey:` / `Bearer ` 这类标签、行尾的逗号分号；
- **去掉了会说出来**：「粘进来的内容里有换行，已自动去掉」；
- **密钥框下面显示形状**：`JWT（三段，点号分隔） · 218 字符 · eyJhbG…E4AA`。密钥不回显——
  设置页是会被截图的地方——但填对没有必须当场看得见；
- **只动确定不属于密钥的字符**：base64url 的 `-` `_`、补位的 `=`、分段的点一个都不碰。
  洗坏一把好 key 比脏着更糟，因为人还以为自己填对了。

环境变量那一路同样洗：`export LIFE_COCKPIT_MIAODA_KEY=$(cat key.txt)` 天然带着一个换行。

**为什么邮件不做直连 SMTP**：Obsidian 插件里没有 SMTP 客户端，硬做要么引第三方依赖、要么自己写协议，
还要把邮箱密码存进 vault。指向自己的一个中转（n8n / 云函数 / 飞书机器人都行）是更短也更安全的路。
**这是明说的取舍，不是没做完。**

### 复工前的强提醒页

语音转录原话：「你可能每次恢复工作之前，它可能有一个提示让你去什么页面去每天去看，做一个强提醒」。

「强」体现在两件事上：**拦在工作段前面**（拦着的时候番茄是停的——盯着这一页发呆的三分钟不该被记成专注），
以及**有最短停留时间**（默认 8 秒，按钮在这之前是灰的，秒过等于没看）。

「强」**不**体现在不许退出上：Esc 不放行，但留了一颗「这次先跳过」（设置里可禁）。
锁死的界面第二天就会被整个关掉插件，那前面五轮全白干。

那颗按钮**只跳过这一次**——下一段休息完照样拦，两档频率下都是这一句话。
（0.17.0 之前它叫「今天先跳过」，却从没跳过一整天；想整天不被拦，关的是强提醒页这个开关本身。）

页面按天轮换：同一天里反复被拦看到的是同一页，换一天才换一页——「每天去看」这句话才落得下来。
用的是禅定那块遮罩，**没有另起一套**：同一块屏幕上不该有两套盖法。

### 每日推荐读物与学习资料

料**全部来自现成的地方，一条都不是现造的**：

1. 候选区里 `类型: news-digest` 的夜班 N 次方总结（S1）；
2. 休息页里配了路径的那几篇（R1）；
3. 复盘素材包（R5）——昨天的自己写给今天的，空的那一天不推；
4. 读物池：设置里一行一条，**可选**，默认空。

四类**轮着取**而不是按类排队：资讯多的日子，按类排队会把精品阅读和复盘挤得永远轮不上。
挑选**按天确定性轮换，不随机**——随机推荐在个人系统里有毒：今天推没推过、看没看完，第二天全说不清。

推荐挂在强提醒页上：人被拦下来的这几秒，是一天里最可能真的看一眼的时刻。

#### 强提醒页上的推荐点得开了（0.11.0 修）

> 「复工前的读物提醒里面，我点击了 比如【阳明心学】——然后在 点击 我已读，之后
>  看到【对应页面】并未在【Obsidian】中打开。」

**是 bug。** 那块遮罩挂在 `document.body` 上，**在 workspace 之外**——Obsidian 那套
「点 `[[内链]]` 就跳过去」的默认行为够不着它。于是渲染出来的推荐是一串
**看着像链接、点了什么都不会发生**的东西；页面上那颗按钮也不叫【我已读】，
它叫【看完了，开工】，按下去只是过闸。两件事凑在一起，看起来就像「点了已读，然后什么都没发生」。

改了三处：

1. 推荐那一栏不再走 Markdown，**每一条都是一颗真的按钮**，点击直接开笔记；
2. 遮罩正文里的链接也自己接了——强提醒页 / 休息页那篇笔记里的 `[[内链]]` 和外链，
   以前同样是死的，现在内链走 `openLinkText`、外链交给系统浏览器；
3. 点开之后**弹一条回执**：「已经打开《阳明心学》，就在这一页后面——按【看完了，开工】就看得到」。
   笔记只能在遮罩**后面**打开（闸门不能因为点了篇文章就放行），没有这条回执，
   人看到的仍然是「点了一下，什么都没发生」。

#### 读物池可以直接填目录（0.10.0）

**0.9.0 及以前只认单篇 `.md` 路径**——要读一整个目录，得把里面每一篇都手抄一遍，
目录里多一篇笔记就得回设置里改一次。那不是配置，那是维护。

0.10.0 起：**不以 `.md` 结尾的一行按目录展开**，目录里的每篇笔记都进池子。比如儒释道那三块，
一行就够（填完设置页当场会告诉你展开成了几篇——展开成 0 篇通常就是路径写错了）：

```
Root/【2A-META】AI-First时代，知识库（toAI完全公开）/AI-First时代，知识库（toAI完全公开）/人文社会科学
```

那个目录下现在是《论语》《道家》《佛家》《阳明心学》《圣经》《康德》《黑格尔》《横渠四句》一到四、《千字文 · 入门》
这十来篇，于是每天从中轮一篇进推荐。**展开结果按路径排序**，不按 vault 给的顺序——
轮换是按天取第 N 个，顺序不稳的话「换一天必然换一篇」就不成立了。

想只取其中几篇就照旧一行一个 `.md`；两种写法可以混着填。

### 强制休息与系统级锁屏

R1 只做到插件内全屏遮罩，这一轮补上真锁。**它是整个插件里唯一不可逆的动作**，所以：

- **默认关**；
- 真锁之前有倒计时（默认 20 秒），倒计时里能「推迟」（Esc 也是推迟）、能「今天豁免」；
- 只在休息段锁，默认只在长休息锁。

| 平台 | 怎么锁 |
| --- | --- |
| macOS | `CGSession -suspend`（默认），或 `pmset displaysleepnow`（要配合系统的「唤醒时要求密码」） |
| Windows | `rundll32.exe user32.dll,LockWorkStation` |
| Linux 及其它 | **做不到。** 桌面环境太杂，没在真机上验过的命令不写进来充数 |

锁不动的机器上一次都不提——提了也执行不了，纯噪音。锁屏失败会明说失败，不假装锁上了。

## 强制干扰（0.7.0）

推动器负责**说话**，这一层负责**人不听的时候怎么办**。出处是 AME-238：

> 临近番茄钟执行完时，会有 3 分钟的高频次系统通知（每 1 秒到每 2 秒一次）+ 系统亮度渐变切换调整（缓速闪烁的干扰效果）。
> 进入休息时间之后——先强制锁屏——然后给预先设定的正常休息时间。
> 如果休息过后人没有点击【恢复 继续番茄】——则每 1 分钟检查一次，如果仍然是【空闲 + 未恢复工作】，
> 则【强制锁屏 + 弹出通知 + 弹出督促自律网页 + 屏幕亮度缓速闪烁】，强制干扰、强制打断。

0.6.x 缺的就是这一层，缺的后果写在同一条 issue 里：强提醒页拦下来了，人去做家务、睡了两个多小时，
回到电脑桌前**手动切到 Obsidian** 才发现番茄卡在那儿。拦是拦住了，但**拦这件事本身没有任何人知道**——
不发声的强约束等于没有约束。

### 三个阶段

| 阶段 | 触发 | 做什么 |
| --- | --- | --- |
| 临近收工 | 工作段剩余 ≤ 3 分钟（可配） | 通知连击（默认每 2 秒，同 tag 替换 + renotify）+ 蜂鸣 + 屏幕亮度缓速闪烁 + 任务栏闪烁，一直到这一段跑完 |
| 进入休息 | 休息段开始 | **先锁屏**（默认留 5 秒反悔，可设成 0 = 立刻），然后正常休息 |
| 休息结束没复工 | 工作段开了但没跑起来（强提醒页拦着 / 没点开工） | 宽限 60 秒后每 60 秒催一轮，每轮吵 20 秒。**空闲**：闪 + 通知 + 锁屏 + 开督促自律页；**人在电脑前但没复工**：闪 + 通知 + 把 Obsidian 拽到前台，**不锁屏** |

### 三条硬规矩

1. **锁屏只锁空闲的机器。** 人在别的窗口里干活时锁屏，锁掉的是他正在做的事——这种插件第二天就会被卸载。
   「空闲」的口径是**全系统**最后一次输入到现在（默认 60 秒），不是「Obsidian 窗口里没动静」。
2. **默认不收手**（0.8.0 改）。0.7.0 默认催满一小时就安静下来，理由是「凌晨三点还在闪屏不是自律」——
   理由没错，但那是插件替人决定「可以放过自己了」。AME-239 的原话是：
   「如果 “应该开工而没有开工” 则应该 永远是提示！！！」。所以收手改成一颗单独的开关
   （设置 → 强提醒 · 锁屏 · 干扰 → **催不到人就收手**），默认关；打开之后才用下面那个时限，
   收手时留一条「不催了」，番茄原地停着，回来点一下就接着跑。
3. **静音管的是「别吵」，不是「别管我」。** 按下静音之后通知和蜂鸣停，**亮度闪烁与锁屏照旧**。

### 为什么连击不走推动器那五道闸

推动器的冷却（默认 10 分钟）和每日配额是为了「别把人吵到把功能关掉」，按每条消息算——
3 分钟的连击到它手里会被掐成 1 条。强制干扰是人自己点名要的吵闹，所以直接走系统通知，
只留一道闸：人明确按下的静音。

通知用**同一个 tag + renotify**：每次都重新响，但通知中心里始终只留一条。
90 条独立通知会把通知中心刷成一整屏，第二天人就会去系统设置里把 Obsidian 的通知整个关掉——那才是真的失去这一路。

### 屏幕亮度：Windows 走 WMI，调不动就明说

```powershell
(Get-WmiObject -Namespace root/WMI -Class WmiMonitorBrightnessMethods).WmiSetBrightness(1, 60)
```

波形照原话：`100 - 80 - 60 - 40 - 20 - 0 - 20 - 40 - 60 - 80`，每档默认 400 毫秒，一圈 4 秒——**缓速闪烁，不是频闪**。

- **一个 PowerShell 进程跑完整段闪烁**，不是每档起一个进程：起一次 PowerShell 要 200–400 毫秒排不上，
  更要紧的是它自带 `Start-Sleep`，**扛得住 Chromium 的后台节流**（人切走之后 Obsidian 是隐藏窗口，
  渲染进程的定时器会被压到每秒一次、五分钟后每分钟一次——而「人切走了」正是最需要这段干扰的时刻）。
- 命令走 `-EncodedCommand`（UTF-16LE + base64），不拼引号。
- 被中途叫停时进程是被 kill 的，跑不到脚本结尾那句还原，所以**杀完由插件补一条还原命令**——
  不补的话人会得到一块停在 20% 亮度的屏幕，还完全不知道是谁干的。
- **WMI 只管内置显示器**（笔记本屏、一体机）。外接显示器走 DDC/CI，这条路够不着：那种机器上会明说
  「调不动」，退回**遮罩闪烁 + 任务栏闪烁**兜底，不假装成功。设置页里有一颗「测一次亮度」当场看结果。
- **macOS 那一端还没做**：先把 Windows 一端用稳，再谈兼容其它端（AME-238 原话）。锁屏本身两端都有。

### 后台节流

强制干扰开着时，插件会调 `webContents.setBackgroundThrottling(false)` 关掉这个窗口的后台节流，
卸载时还回去。不关的话，AME-238 那两个小时里插件的心跳大概每分钟才跳一下——
最需要它醒着的时候它在打盹。代价是这个窗口在后台也照常耗电。

### 停留倒计时认人不认表

同一条 issue 的另一半：那一页显示着「看完了，开工」，但**人根本没看**——倒计时按墙上的钟自己走完了。

0.7.0 起，最短停留只在**人真的看着这一页**时才走：窗口在前台、可见、而且系统最近有输入。
不在看的那一段时间会被原样加到起点上，于是「还差多久」永远等于「停留时长 − 已经看进去的时间」。
倒计时停着的时候，这一页上会直接写出来（`倒计时停着：不在电脑前 · 空闲 137 秒`）——
一块不说话的表只会被读成坏了。**看满之后就定格**：中途走开不倒扣，看完了就是看完了。

掉拍也不白送：一拍跨了一分钟（后台节流的典型值），最多按 5 秒记账，剩下的算没看。

想退回 0.6.x 的墙钟行为：设置 → 强提醒 · 锁屏 · 干扰 → 复工强提醒页 → 关掉「倒计时只在你真的看着时才走」。

#### 0.8.0 补的那个洞：焦点不是人

0.7.0 修完之后，AME-239 又报了一次同样的现象——**催了 60 分钟之后，那一页自己变成了「看完了，开工」**。

来路是这样的：催促的每一轮都会把 Obsidian 拽到人脸前（`focusMainWindow`），
而 0.7.0 把 `window` 的 `focus` 事件也算成「一次输入」。于是在**拿不到系统空闲时间**的机器上
（Electron remote 不通、PowerShell 兜底也失败），插件自己伪造了一次「人回来了」，
接下来的一分钟里停留倒计时就名正言顺地往前走——**它是被自己的催促推完的**。

修法两条，都很短：

1. **窗口焦点不再算输入。** 只认指针、键盘、滚轮——窗口可以被程序抢到前台，手不能。
2. **锁屏和拽窗口之后，一律先当作没人在**，直到真的有一次指针 / 键盘事件。
   刚被插件锁掉的机器前面，没有人在看任何东西。

另外，就算倒计时真的走完了，那也只是**按钮变得可点**——0.8.0 起，工作段永远不会因此自己跑起来。

### 和老的「强制休息与锁屏」是两条路

它们各有各的开关，**故意不合并**：老那条是 R6 的「休息段提议锁屏」（默认关，20 秒倒计时）；
这一条是「人不听的时候怎么办」（默认开）。合成一个开关的话，已经装过 0.6.x 的机器上
`lockEnabled: false` 早就存进 `data.json` 了——新功能会一出生就是哑的，正是这条 issue 抱怨的事。

### 运行时音乐

日记模板那一行「更改【运行时】音乐，为【常成 - 狮子吼六字真言】」。
「运行时」是关键词：工作段一首、休息段另一首，跟着番茄自己换，暂停就停。

**插件不内置任何音频文件**，曲目路径指向 vault 内的文件，默认空 = 不放。

## 存在感：悬浮提示 · 心跳提醒 · 任务栏（0.8.0）

出处是 AME-239：

> 得需要一些【托盘区的提示、展示】…… 或者，桌面上，有一个悬浮（不可点击、不可交互）的提示框？
> ——中间的提示太弱了，几乎没有存在感——我的预期，每 2 分钟 得有一个提示、提醒？

前面几轮把「说话」全押在了两个地方：Obsidian 窗口里的遮罩，和出事时才炸一轮的强制干扰。
两者中间是空的——**人切到别的窗口去干活的那 25 分钟里，这套系统在他视野里根本不存在**。

| 手段 | 看得见的前提 | 强度 |
| --- | --- | --- |
| 桌面悬浮框 | 什么窗口在前台都看得见（置顶 + 点击穿透） | 常驻、弱 |
| 任务栏进度 / 闪烁 | 余光扫得到任务栏 | 常驻、更弱 |
| 心跳提醒（默认每 2 分钟） | 系统通知 | 周期、中 |
| 强制干扰 | 亮度闪烁 / 锁屏 | 事件驱动、强 |

### 悬浮框

Electron 另开的一扇小窗：**置顶（`screen-saver` 级）、点击穿透、不抢焦点、不进任务栏、不进 Alt-Tab**。
显示当前是工作还是休息、还剩多久、第几个番茄、在做什么、当日累计；
**欠着一次开工时整块变红**，而且那时它不走秒——一块自己往前跑的倒计时会让人以为番茄在跑。

秒表由那一页自己走（插件只在状态变了时推一次），所以**即使插件这边被 Chromium 压到每分钟一跳，
贴纸上的数字也是准的**。

拿不到 Electron 的 `BrowserWindow` 时（或者你自己把「开一扇真正的桌面悬浮窗」关掉），
退回**画在 Obsidian 窗口里**的一块浮层——那时切走就看不见了，**设置页会照实说这一点**，
不假装它一直在。设置 → 界面 → 悬浮提示，有一颗「闪一下」当场验。

#### 它跟着 Obsidian 一起走（0.17.0 修）

0.16.0 及更早：**点【退出 Obsidian】之后这块贴纸还留在屏幕上**，再打开 Obsidian 就叠出第二块
（AME-273 第 3 条）。病根是它是另一扇真窗户，而它的寿命从前只挂在插件的 `onunload` 上——
退出这条路根本不走那个钩子。窗还开着，Electron 那句「窗都关完了才退进程」就永远等不到，
于是进程留着、贴纸留着，下一次打开再叠一张。（走【重启 Obsidian】反而正常，因为它走的是另一套收尾。）

现在寿命有三条腿，断一条另外两条还在：

1. **主窗要走时自己关**（`beforeunload`）——退出 / 重启 / 重载三条路都经过它；
2. **开之前先扫一遍有没有前任**——按窗口标题这个记号认（只认全等，绝不误杀你的 Obsidian 主窗），
   上一版留下的孤儿窗也在这里被收掉，所以**升上来的第一次开窗就把重叠的那一张清了**；
3. **贴纸自己有个看门狗**——超过 5 分钟收不到插件的心跳就自尽。插件被强杀、渲染进程崩掉时
   只剩这一条；机器睡一觉醒来那种「一跳几小时」不算数（那一跳里它自己也停着，说明不了什么）。

### 心跳提醒

默认每 2 分钟一条（可配，可填小数）。它**绕开推动器那五道闸**（冷却 10 分钟、每日 24 条）——
按闸门算的话第一拍之后就全被吃掉了；只留一道闸：你按下的静音。

- **正在被强制干扰时让路**：闪着屏还插一条「工作中，还剩 12 分钟」只是噪音。
- **起拍点是状态变化那一刻**，不是插件装载那一刻：刚点下开工就挨一条不是节拍，是骚扰。
- 「该开工却没开工」那一格**永远心跳**，不受「番茄正常跑着时也提醒」那个开关影响。

### 托盘 vs 任务栏，说清楚做不到的那一半

**插件够不到真正的系统托盘图标**：`Tray` 要在主进程里建、要一张 nativeImage、还得有人管它的生命周期，
而插件跑在渲染进程里。够得着的是**任务栏按钮上那条进度**（`setProgressBar`）：
工作蓝、休息黄、**欠着开工红**，外加心跳那一下的任务栏闪烁。

## 界面字号（0.8.0）

> 整体的字体，应该要大一点——因为我的 Obsidian 面板的【Interface——Advanced——Zoom Level】，是缩放到了【83%】左右。

所以这是**一个全局倍数**（设置 → 界面 → 字号，默认 120% ≈ 1 / 0.83），不是一堆各自为政的字号：
面板、目标树、候选区、全屏遮罩、悬浮框、弹窗一起跟着变，Obsidian 自己的界面不受影响。
换一台电脑就改这一个数。

实现上，插件往 `document.body` 挂一个 `--life-cockpit-scale`，`styles.css` 里每一块界面只在**根节点**
换算一次，里面一律用 `em`——所以那个文件里不该再出现 `font-size: var(--font-ui-*)`（绝对值会绕过缩放）。
设置页本身**不吃**这个缩放：只把自己几节放大，会和设置窗里其它插件的排版打架。

## 设置页

最上面是**新手 / 专家的档位切换**（见上面《新手 / 专家两档设置面》），它自己永远不灰。
下面一排标签页，十九节分进八页，一次只画当前那一页：

| 标签页 | 里面有 |
| --- | --- |
| 界面 | 字号、悬浮提示 · 心跳提醒 |
| 番茄 | 模式（含间歇节奏）、当日累计、重启与状态延续、番茄流水 |
| 节律 · 禅定 | 五行节律表、禅定模式、运行时音乐 |
| 账本 · 目标 | 积分账本、目标树 |
| 交班 · 复盘 | 夜班候选区、睡前复盘、飞书金字塔表格 |
| AI 接口 | AI 接口（档位表 + 谁在用它）、调用记录 |
| 推送 · 推荐 | 主动推送、每日推荐读物 |
| 强提醒 · 锁屏 · 干扰 | 复工强提醒页、强制休息与锁屏、强制干扰 |

分法按**使用场景**，不按代码分层——所以「运行时音乐」虽然实现上属于 R6 推动器，却和禅定、节律放在一起：改它的时候想的是工作段听什么。
**AI 接口 0.11.0 起单独一页**，理由相反：它是被好几处共用的一层，藏在其中一处底下，第二处接进来的那天就要搬家。

多行输入的那几项（读物池、提醒主题）是**说明在上、输入框占满整行**：Obsidian 的设置项默认左右分栏，
说明越长输入框越窄，而「说明写多长」和「输入框有多宽」本来就不该是此消彼长的关系（AME-258 第 22.3 条）。

每个小节的标题后面跟一行状态（`已开` / `已关` / `静音中` / `已开（锁不动）`），扫一眼就知道哪些开着，不用挨个点进去确认。当前停在哪一页记在设置页实例上：关掉设置窗再打开还在原来那一页，重启 Obsidian 回到第一页。

改一个开关只会重画它自己那一小节，**不会整页重建、不会跳回顶部**（0.6.2 以前会，见 AME-227 Bug2）。

标签页是自己搭的，没用 Obsidian 1.13 的声明式设置 API（`getSettingDefinitions()`）——那套要求 `minAppVersion` 抬到 1.13.0，这个插件要继续照顾旧版本。代价是这些设置进不了 1.13 设置窗的全局搜索。

## 冷启动：目标树 / 积分任务表读不到怎么办

0.6.1 以前有一个冷启动竞态（AME-227）：关掉 Obsidian 再打开时，插件的 `onload` 排在 vault 建索引之前，那会儿 Obsidian 对着一份真实存在的笔记也会说「没有这个文件」。表现是目标树下拉一个选项都没有、积分面板提示「任务表还没建」、余额显示成 0——**但手动在设置里启用插件一切正常**，因为那时索引早就建好了。

0.6.1 起，所有初始读取改在布局就绪之后跑，读文件还多了一层兜底：索引里查不到就直接问文件系统。

万一还是撞上（索引落后得离谱、或者刚在别处改过设置里的路径），账本与目标树会**拒绝落盘**并报一句「……已经在盘上了，但这次载入没读到它」。这是有意的：它们都是整份重写的，读空之后再写就是把你写的东西抹掉。照提示跑一次命令面板里的「重读积分账本」/「重读目标树」，读到了就能继续记。

## 不在本插件范围内

- 直连 SMTP 发邮件（见上面「渠道」一节的取舍说明；走通用 webhook 接自己的网关）。
- Linux 上的系统级锁屏。
- macOS 上的屏幕亮度闪烁（锁屏那一端两个平台都有；亮度先把 Windows 做稳）。
- 外接显示器的亮度（DDC/CI），WMI 够不着——那种机器上退回遮罩 + 任务栏闪烁。
- **真正的系统托盘图标**：那要主进程建 `Tray`，插件跑在渲染进程里够不着。够得着的是任务栏进度与闪烁。
- 移动端。
