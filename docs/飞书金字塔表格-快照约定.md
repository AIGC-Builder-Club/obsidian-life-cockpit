# 飞书金字塔表格 · 快照约定

人生驾驶舱读飞书表格，读的是**一份快照 JSON**。这份文档是那个文件的格式约定——
不管快照是谁产的、怎么来的，两条路读的都是这一套格式。
为什么这么设计见[人生驾驶舱文档](人生驾驶舱-LifeCockpit.md)的《飞书表格：接一栏，不搬一张表》。

## 这份快照在整条链里的地位

**先把主路和旁路分清楚**——它们的门槛差得远：

- **主路（日常真正在跑的这条）**：插件里的四个入口触发 Convex 的 `feishu:requestPull` 起一个 job，
  一台带 `lark-cli` 的执行机按 `jobId + attempt` **先推最新快照、再写回【总结】页**。
  这条路**要 Convex 后端加一台执行机**，属于第三、四阶段，不是「装上就能用」。
- **旁路（降级方案）**：手动把一份导出好的快照 JSON 放进 vault。零依赖，不需要 lark-cli
  也不需要 Convex——但**仓库主人自述这条他自己用得很少**。想认真用这一栏请走主路，
  旁路只是「不想接后端时也让这一栏不空」。

## 边界先说清楚

**记录仍然发生在飞书上。** 插件不在 Obsidian 里造第二张任务表，**也不直接调飞书 OpenAPI**——
它不碰 app id / app secret / user token。但**「插件不直接调飞书 API」不等于「插件不需要后端」**：
主路上插件负责给出入口、触发 Convex job、读回快照，真正读写飞书的自始至终是执行机上的官方 `lark-cli`。

## 文件放哪儿

```
LifeCockpit/飞书快照/
  2026-08-18.json
  latest.json        ← 可选，懒得按日期命名就用它
```

目录在设置里可改（设置 → 交班 · 复盘 → 飞书金字塔表格 → 快照目录）。默认值和运行区里
其它数据面挂在一起——**如果你也让夜班 Agent 读这份快照，就得把它放在它够得着的仓库里**；
那是作者自己的用法，不是这份约定对所有人的硬性要求。只给自己用的话，vault 里哪儿都行，
把设置里的快照目录指过去就好。

插件找文件的顺序：

1. `<快照目录>/<今天>.json`
2. `<快照目录>/latest.json`
3. 目录里日期最大的那一份 `YYYY-MM-DD.json`

第 3 条不是兜底，是**常态**：快照是隔几天才更新一次的东西，只认当天文件的话这一栏一年里
有大半年是空的。读到的不是今天那一份时，面板和复盘正文都会写明「这是表上最近有记录的一天」。

## 格式：直接吃导出管线的产物

**首选写法就是把 `all_tasks.json` 原样拷过来**，一个字节都不用改：

```jsonc
{
  "generated_at": "2026-07-27T14:34:24+08:00",
  "all_tasks": [
    {
      "sheet": "2026年07月02日 周四",
      "text": "看完一整本书吧？",
      "status": "完全没去做",
      "difficulty": "中难",
      "side": "个人兴趣"
    }
  ]
}
```

另外两种也认（约定定得复杂，就没人遵守）：

```jsonc
{ "generated_at": "…", "tasks": [ … ] }
[ … ]                                    // 裸数组，最省事
```

`generated_at` / `source_url`（也认驼峰 `generatedAt` / `sourceUrl`）可选，填了会显示在面板上——
「这份快照有多旧」是人一眼就想知道的事。除这几个键之外的字段一律原样忽略，
所以导出管线里的 `rules` / `diagnostics` / `ignored_cells` 留着不碍事。

### 每一条用得上的五个字段

| 字段 | 说明 |
| --- | --- |
| `text` | 任务原文。**空白的不是任务**，会被丢掉 |
| `sheet` | 日期从它解：`2026年07月02日 周四` → `2026-07-02` |
| `status` | 四选一：`已完成` / `完成了一部分` / `完全没去做` / `未知状态` |
| `difficulty` | `高难` / `中难` / `低难`；判不出来留空串 |
| `side` | `工作内容` / `个人兴趣`；判不出来留空串 |

也可以直接给 `day`（`YYYY-MM-DD`），给了就不解 `sheet`。

**什么不算任务**（照抄 SOP《解析规则》，别另起一套）：空文本、`50` / `300` / `1000` 默认分值、以及形如 `(1000)（1/5）` 的模板分值/配额占位符。这一条**必须在压换行之前判**——
占位符长的就是 `(1000)\n\n（1/5）`，压完更像一条正经任务。

> 这不是假想的风险：仓库里那份快照 177 条里有 38 条是占位符，全被记成「完全没去做」，
> 「还欠什么」99 条里 35 条是假的，完成率从 54% 被压到 42%。上游本该滤掉，
> 但那份快照是规则加进去之前导的——**这一页会被写回飞书当事实读走，所以这边再滤一道。**

两条读法上的规矩：

- **解不出日期的不算进任何一天**（模板页 `模板(直接创建副本)` 就是这种）。那不是错误。
- **认不出来的状态一律落到「未知状态」，不假装已完成。** 表上填了个别的颜色，
  它该出现在「还欠什么」那一栏里等人复核，而不是被静默算成做完了。

## 怎么产这份快照

导出那条路已经跑通了，在有 lark-cli 的机器上：`lark-cli sheets +export` 拉最新 xlsx →
按单元格填色判难度与完成度 → 产 `data/structured/all_tasks.json`。日常主链由 Convex job
派自动化运行 `backend/life-cockpit/scripts/refresh_feishu_summary.sh`，它会把快照推入
Convex 并写回【总结】页；旧的拷文件 / `git push` / Easy-Git 拉取只作为下位补充。

手写也行——它只是一个 JSON 数组。但**别用模型现编**：这一栏的全部价值在于它是表上的事实。

## 它出现在哪儿

| 位置 | 显示什么 |
| --- | --- |
| 复工强提醒页 | 当天的条目，**没做完的排前面**，排在推荐读物之前 |
| 驾驶舱面板 | 一行状态 + 「打开表格 / 重读快照」 |
| 复盘素材包 | `feishu` 那一栏：计数 + 已完成 / 没做完的**原句** |

素材包里那一栏长这样（没有快照时**连这个键都不写**）：

```json
{
  "feishu": {
    "day": "2026-08-16",
    "url": "https://my.feishu.cn/wiki/…",
    "generatedAt": "2026-08-16T22:10:00+08:00",
    "total": 12, "done": 5, "partial": 2, "notStarted": 5,
    "finished": ["…"],
    "pending": ["…（完成了一部分）"]
  }
}
```

**原句进素材包是有意的**：番茄流水记的是时间去处，飞书表格记的是事情本身。
「我每天都大概干了什么、我是一个什么方向的人」这一问，只有原句答得了，计数答不了。

## 反过来的那一半：【总结】页写回飞书

出处是 AME-271 第 28 条——**把原本要出的那份报告，直接变成表自己的一页**：

> 「你其实可以在那个飞书的 Excel 那个文档的 SOP 的 py 脚本，去让他自己去插入一页【总结】……
> 这样，会非常方便查看——并且，也方便后续的读取（无论是人还是 AI Agent 去读取）……
> 最好包括相关的一些任务链接都可以鼠标点击过去，之后直接跳过去，方便我去做一个关闭……
> 这样长期以来也是一个很大的一个人的 issue 库。」

### 边界重划了一次

上面那一节说的「插件不写飞书 API」仍然成立，但**整条链第一次有了写的方向**。
边界因此从「读还是写」挪到了「哪一页」：

| | 谁是权威源 | 谁会写 |
| --- | --- | --- |
| 日期页（人手填的那些） | **人和那张表**。一个字都不碰 | 只有人 |
| 【总结】页 | 没有权威源，它整页都是派生物 | `write_feishu_summary.py`，**整页重写** |

这条线划得住，是因为总结页上没有一格是原创数据——它全部由日期页算出来。
派生物被覆盖不丢东西。所以那一页的**页首第一屏就写着「在这里手改会被覆盖」**：
要改请改对应的日期页。

**写的人仍然不是插件。** 插件这一侧只多了一个点得开的入口
（设置 → 交班 · 复盘 → 飞书金字塔表格 → 【总结】页地址）。

### 那一页上有什么

六段，一共 6 列：

| 段 | 回答什么 |
| --- | --- |
| 页首 | 更新于什么时候（带 `+08:00`）、快照多旧、覆盖哪一段日期、**手改会被覆盖** |
| 一、总览 | 共多少条 / 已完成 / 部分 / 没动 / 未知 / 完成率 |
| 二、还欠什么 | **按日期从早到晚**，欠得最久的排最上面。任务原文是链接，点一下跳到那一天那一页 |
| 三、做完了什么 | 按日期从晚到早 |
| 四、按天 | 一天一行 + 跳到那一页 |
| 五、按目标 | 目标树上的【飞书关键词】决定归属；**挂不上目标的那一栏永远出现，哪怕是 0** |
| 六、这一页是怎么来的 | 产它的脚本、以及口径 |

第二段就是他说的那个「人的 issue 库」，所以排在最前面、从早到晚：
按日期倒序会让老账沉到底下，而沉下去的老账等于不存在。

**链接精确到格**：`<表格地址>?sheet=<sheetId>&range=<单元格>`。

> ⚠️ 更正一条：上一版这里写的是「`all_tasks.json` 里没有行号，所以只能跳到页」。
> **那是没看实际产物就下的结论——它有。** 真实导出的每一条都带
> `coordinate`（以及 `row` / `column`），所以链接能直接落到那一格。
>
> 页那一级是确定的（那就是仓库主人贴过来的地址形态）；`&range=` 这一段
> **没有对着官方文档核实过，是尽力而为**。敢挂是因为失败的方向安全：
> 飞书不认这个参数时会忽略它，落点退回「那一页」，和不挂完全一样。

解不出单元格的条目退回页级跳转，拼不出链接（页改过名、没配表格地址）的
退回纯文本，**不放一个点了没反应的假链接**。

### 谁算、谁贴

```
Obsidian 插件 → `feishu:requestPull` → Convex job
   └─→ 自动化运行 refresh_feishu_summary.sh
          ├─→ 导出管线产 all_tasks.json → push_feishu_snapshot.py 推进 Convex
          └─→ write_feishu_summary.py     ① 认表 ② 问飞书要页清单
                                   ③ POST /hooks/feishu-summary/plan  ← 后端算出整页格子
                                   ④ 建页（缺的话）→ 整页重写
                                   ⑤ POST /hooks/feishu-summary/done  → 收口 job + 插件面板亮起来
```

**版式和口径全在后端**（`backend/life-cockpit/convex/lib/feishuSummary.ts`），
脚本里一行业务判断都没有。理由：跑脚本那台机器上没有目标树、没有账本、
也没有第二份口径，把判断放在那儿等于把口径复制一份到一台谁也测不到的机器上。
放在后端，这一页的样子能被 `node --test` 钉住，改版式不用碰那台机器。

**顺序不能反**：先推快照再写总结，否则写的是昨天那一份。脚本已经把两步固定成一条链；
插件通过 `jobs:watch` 读取 `pending → running → succeeded/failed`，不再靠 Easy-Git 的文件
mtime 猜完成状态。成功的 `done` 回执会用派发时的 `jobId` 精确关闭对应的
`feishu-snapshot` job；旧手工脚本才退回同日 + 时间匹配。没有成功回执的运行由
stale-job 扫描收口为失败。

### 后端还没就位时：本机算那一页

上面那条链要求 Convex 上已经部署了 `/hooks/feishu-summary/plan`。**第一次跑的时候它还不在**
——而「为了看第一份结果，先要求一整套后端就位」是没道理的。所以有第二条路：

```bash
python3 write_feishu_summary.py \
  --tasks all_tasks.json \
  --goals <vault>/驾驶舱运行区/目标树.md      # 可选，读 [飞书:: 关键词]
```

给了 `--tasks` 就不连 Convex：脚本改在本机跑 `build-summary-grid.mjs`。
**那个脚本 bundle 的就是后端那份 `convex/lib/feishuSummary.ts`**，所以两条路算出来的
是同一段代码产的格子，不是第二个实现。这条路下不落回执（没有后端可报），
插件数据台上那一格要等接上 Convex 才会亮。

这条路要 `node` 和 backend 的 `esbuild`（`cd backend/life-cockpit && npm install` 一次）。

### 要填的东西

跑脚本那台机器上（**凭据不进仓库**）：

| 变量 | 说明 |
| --- | --- |
| `LIFE_COCKPIT_FEISHU_DOC_URL` | 表格地址，wiki 链接或 sheets 链接都行 |
| `LIFE_COCKPIT_CONVEX_SITE` / `LIFE_COCKPIT_CALLBACK_SECRET` | 和推快照那条同一对 |
| `LIFE_COCKPIT_JOB_ID` / `LIFE_COCKPIT_JOB_ATTEMPT` | Convex webhook 触发时从载荷成对透传；手工运行可都不填 |

飞书 user 凭据由 `lark-cli auth login --domain sheets,wiki,drive` 存进系统钥匙串，脚本不接触明文。
知识库链接和 sheets 链接都直接贴浏览器地址栏里的值，解析交给官方 CLI。

先跑 `--dry-run` 看一眼那一页长什么样，一个字都不会写。

## 待仓库主人确认

1. 快照要不要定个保留期——它会天天长，而且随仓库公开。
2. 那张表里有没有不想公开的条目。要是有，快照这一步就该先过滤，而不是整本拷进公开仓库。
3. 拷快照这一步要不要接成自动的（导出管线跑完直接写进 2A-META 的 checkout 再 push）。
4. 【总结】那一页默认建在**最前面**（`--sheet-index 0`），会把现有页往后挤一位。
   想放别处就改这个参数；已经存在同名页时不动它的位置。
