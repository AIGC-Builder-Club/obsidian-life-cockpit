# 人生驾驶舱 Life Cockpit 设计取舍

自研插件，源码在 `plugins/life-cockpit/`，可安装产物在 `dist/life-cockpit/`。用法和流水 schema 见插件自己的 [`README.md`](../plugins/life-cockpit/README.md)，本文只记为什么这么做。

## 它解决什么

2A-META 里那张作息表——`金一 木二 水三 火四 土五` × `早起 / 三小时工作日 / 双数日 / 单数日 / 睡觉`——原本是**画在日记模板里的一张 Markdown 表**。表本身不会提醒你现在该干什么，也不知道你今天专注了多少分钟。本插件把这张表和它旁边那段「14 小时工作制、560 分钟番茄、25+5、禅定模式」的文字，变成会跑的东西。

## 为什么直接住在合集仓库

先例是 RefBake（`dist/obsidian-ref-bake/`）：自研内容不单开仓库。独立仓库 + submodule 那套是给**二开**插件用的（Easy-Git），成本花在跟踪上游上，自研没有上游。

区别在于 RefBake 是单文件 Templater 脚本、无构建，可以整个塞进 `dist/`；本插件要 TS + esbuild，所以源码单独占一层 `plugins/life-cockpit/`，产物仍然落 `dist/life-cockpit/`。README 里的「自研脚本直接放 `scripts/`」相应扩成「小脚本放 `scripts/`，要构建的自研插件放 `plugins/`」。

工程形态（TS + esbuild + `manifest.json` + `node --test` + eslint）直接照 `Easy-Git-Maintained` 抄，没有另造模板工程。

## 纯逻辑与 Obsidian 隔离

`src/core/` 下不许 `import "obsidian"`。`node --test` 只 require `src/core` 打出来的一个 CJS 包（`pretest` 里用 esbuild 打，产物在 `test/.build/`，不入库）。

这不是为了「纯 JS 核心」那套架构洁癖，只是为了让计时状态机、时段判定和流水读写幂等这三件事**能在没有 vault 的机器上被测到**——恰好也是 AME-180 验收条件第 9 条点名要覆盖的三件事。UI、落盘、通知这些碰 Obsidian 的部分不进 `core`，也不写单测，靠 vault 内实测。

R6 把这条线拉到了推送上：`PushHub` 的渠道是**注入**的，所以 `node --test` 里拿两个假渠道就能把
「五道闸 → 分发 → 一条渠道炸了别的还得发出去」整条链路跑真的。同理，锁屏的命令表是 `core` 里的纯数据，
真正 spawn 子进程的那一下在 `src/desktop.ts`——**整个插件只有那一个文件碰 `window.require`**。

## 时间语义上的几个决定

**一天从凌晨 4 点开始。** 14 小时工作制会跨零点，睡觉段本身就是 22:00 → 05:00。按自然日归档的话，01:30 收工那个番茄会被记到第二天，当日进度天天缺一截。默认 4 点换天，设置里可改成 0 点回到自然日。

**空档就是空档。** 原表 12-13 和 17-18 是空的，插件也保持空——落在空档时「当前时段」返回「无」，不替表主人补一个「午休」出来。

**时段左闭右开。** 09:00 属于三小时工作日，08:59 属于早起，边界不重叠。

**电脑休眠不虚报时长。** tick 迟到几个小时的时候，只记计划内的时长（25 分钟），不把休眠的三小时算成专注。

## 五行列对应哪天——这是推断，不是原文

原表只给了五个列头，没写哪天走哪列。`一二三四五` 在中文日常语境里最自然的读法是周一到周五，所以默认取 `weekday` 映射，周末没有对应列。同时实现了 `cycle5`（从锚点日起五天一轮，不管星期），设置里一键切，两种都有测试覆盖。

**如果本意是别的对应方式（比如按天干、按农历），改设置即可，不用改代码。** 这里明确记成待确认项，而不是当成既定事实。

## 提醒主题节律

「模式切换会改提醒主题节律」这句，落成两件事：每个模式各有自己的**提醒间隔**和**主题轮换表**。

- 加速实践：25 + 5，每 30 分钟一条主题（对应日记模板里的「每半个小时，提供一波想法」）。
- 思考优先：45 + 10，每 45 分钟一条。

默认主题文本全部从日记模板《今日每日任务》的六维（诚 / 爱 / 当 / 意 / 诚 / 体）里摘的原句，不是新编的。设置里是一个多行文本框，随便改。

切模式时提醒重新对表：新间隔从此刻起算，主题回到第一条，不会把上个模式攒的进度带过来。

离开电脑几小时回来只补一条提醒，不把攒下的一次性倒出来。

## 流水 schema 与积分账本的接口

一天一个 JSON，不是 Markdown：它是机器遥测，秒级、只给插件自己读，JSON 省得再写解析器。

给积分账本预留的位置是 `sessions[].points`、`sessions[].pointsRule` 和顶层 `points`（`earned` / `spent` / `balance` / `entries`）。R1 一律写 `null` / 空数组，**不猜计分规则**；R2 落地之后由账本回填。

关键约束是：**写进这些字段的值，R1 重新加载时必须原样保留。** R1 每次加载都会重算 `totals`（工作秒数、完成番茄数），但重算只碰 `totals`，不碰 `points`。`test/ledger.test.js` 里有一条测试专门守这个边界——R2 落地时这条测试一个字都没改。

## 积分账本为什么是 Markdown（R2）

流水选 JSON、账本选 Markdown，是**两种读者**决定的，不是随手挑的：

- 流水给插件读；账本要在 Obsidian 里被人直接翻、直接搜、必要时直接改。Markdown 表格渲染成表格，JSON 只是一坨纯文本。
- frontmatter 的 `earned` / `spent` / `closingBalance` 变成 Obsidian 属性，Dataview 直接能查。
- 一个月一份、基本只在末尾追加，git diff 干净。

代价是解析要容错，所以定了一条硬规矩：**读不动的行不删，原样搬到文末《待修复》**，人改好了下次读盘自动归位。手工编辑和插件写盘因此可以共存。

其余几个决定：

- **全账读进内存。** 月账文件很小，启动时全读，任意区间查询和跨月余额就都是纯计算，不用维护任何增量缓存去和源头对账。
- **撤销是一笔新流水**（方向相反、`来源=撤销`、`关联` 指回原笔），原笔留在账上。汇总时原笔与撤销单都不计入入账 / 出账，两者相抵为零——所以「这周花了多少分」不会被撤销污染。
- **日档里的积分是派生数据。** 源头永远是账本 Markdown；日档 JSON 的 `points` 位每次写盘整体重算，为的是让睡前复盘（R5）打开一个文件就拿全当天的番茄与积分。日档 JSON 的每一次写入都要过 `PointsStore.applyMirror`，否则插件侧和账本侧会互相把对方写的内容盖掉。
- **读写层也是纯的。** `PointsStore` 的文件访问全部走注入的 `VaultIo`，不 import `obsidian`，所以整条落盘链路（写盘幂等、日档镜像、撤销留痕）都能在 `node --test` 里跑真的，而不是只测中间那层纯函数。

## 睡前复盘为什么不是一个新面板（R5）

复盘是驾驶舱的最后一环，但它**没有自己的视图，也没有自己的回写通道**。两条都是刻意的。

**没有自己的回写通道**，是因为 R4 已经有一条：候选区。复盘要往三个地方写字（日记、目标树、错题本），而这三个地方 R4 的采纳处理器都已经能落——`note` 追加进笔记，`goal-node` 在树上长节点。再造一条「复盘专用回写」只会得到两套人机确认、两套留痕、两处要对账的地方。所以复盘只做到**投候选项**为止，写主干是人按下「采纳」那一下的事。

**没有自己的面板**，是同一件事的推论：产物落在候选区，拍板面就是复盘面。发起的入口塞在拍板面顶上，不另开一张表。

### AI 在哪一段，人在哪一段

「AI 为主、人工为辅」落成两个具体的边界：

- **AI 的输入是一个文件**（当日素材包 JSON），**输出是一个结构**（`ReviewDraft`）。中间没有插件逻辑，所以换模型、换渠道、换成本地脚本都不动主体。这一条照抄 S1 的 `--summarizer`：接口留在数据上，不留在代码里。
- **人的动作是拍板，不是写作。** 人打开的是一份已经填好数字、排好六维的草稿，在上面改，而不是从空白开始。这正是「AI 为主，人工为辅」那句话的字面意思。

### 兜底草稿只算不猜

内置的兜底草稿和 `tools/news-inbox` 的抽取式兜底同一个定位：**确定性、不需要模型、不产生洞见**，存在的意义是夜里模型不通时仍有一份能读的复盘。

边界划在「算得出来」和「判断得出来」之间：完成度和偏差是算的（专注差多少分钟、几个番茄没跑满、几个没挂目标、有没有超支），一律算出来；「明天该改什么」是判断的，只留位置不填。

**`plans` 和 `mistakes` 兜底一律是空数组。** 尤其是错题本——不是每天都有「不贰过」级别的教训，自动往里灌等于把它变成流水账，那样它就不再是错题本了。宁可少记。

### 打回的理由要能读回来

这是 R4 铺好的路，本项只是走上去：打回的候选项**不归档、留在原地**，所以下一轮复盘扫一遍候选区就能把理由读回素材包里，写进下一版草稿的正文。**别在同一个地方栽第二次**——这一条是「系统自己长记性」唯一的机械落点，其余都是人的事。

只认复盘自己投出去的那几条（候选 ID 形如 `<日期>-review-journal|plan|mistake`）。资讯夜班被打回的理由跟这一轮复盘没关系，混进来只会稀释信号。

### 复盘不记账

R4 的处理器里有 `ledger-entry`，复盘一条都不投。理由不是嫌麻烦：**分该怎么记是当场的事**，隔一天由复盘补记，账本上的时间和事实就对不上了，而账本恰好是复盘自己下一次要吃的输入。约定里那条「缺 `方向` / `分值` 直接拒绝，账目宁可不落也不猜」是同一个道理的另一面。

### 睡点为什么按账本日算

提醒默认 22:00，对齐节律表里睡觉段的起点。但判定不是「现在几点」而是「这个账本日的睡点过了没有」：凌晨一点半还没睡的人，按 `dayRolloverHour=4` 还算前一天，睡点早就过了——这时候进门应该补一条提醒，而不是当作还没到点。**一点半还没睡的人更需要这条提醒，不是更不需要。**

一个账本日只提醒一次；手动发起过就不再提醒——人已经在做这件事了。

## 写盘幂等

照抄 RefBake 的 `writeIfChanged`（`dist/obsidian-ref-bake/RefBake.js:655`）：序列化结果和磁盘上一模一样就不写。

为了让「一模一样」真的成立，序列化这边也配合了：JSON 的 key 顺序在 `serializeDayLedger` 里手写死，不靠对象字面量顺序；流水按开始时间 + id 稳定排序，乱序写入和顺序写入得到同样的字节；**没有 `generatedAt` 之类每次都变的字段**。同一段重复落盘会拿到同一个 `id`，覆盖而不是追加。

`scripts/update-life-cockpit-package.mjs` 同步产物时也是先比内容再写，连跑两次第二次输出 `already up to date`。

## 推动器：为什么闸门写在推送之前（R6）

前五轮造的都是**内部**：时间、状态、结构、交班、收口。五样都有同一个前提——人得先坐下来看一眼。
R6 造的是**外界**，依据是仓库主人自己那句「『老板叫回去开会』的『清醒行动迅速』其实是【外界推着你走】」。

难点不在「怎么发出去」——系统通知三行代码。难点在**它极其容易自杀**，而且有两种死法：

1. 推了不看 → 等于没推；
2. 推得太多 → 被整个关掉，**连带前面五轮一起失效**。

第二种更致命，因为它不可逆：一个被关掉的插件不会再有第二次机会。所以闸门写在推送之前而不是之后，
而且是五道：全局静音 → 分级阈值 → 免打扰时段 → 同键冷却 → 每日配额。

顺序是有讲究的：**先判「人明确要求的安静」，再判「系统自己攒的限额」**。反过来的话，
静音期间的消息会白白吃掉配额，解除静音以后反而推不动。

「强制」级只豁免两道——免打扰时段（可配）和每日配额。**全局静音和同键冷却对它一视同仁**：
前者是人的明确指令，后者防的是同一件事连着炸十遍，两样都不该被「这条很重要」绕过。

被拦下来的每一条都记下是哪一道闸拦的，面板上直接显示。这不是日志洁癖——
「今天怎么没推」这个问题答不上来的话，人下一步就是把整个功能关掉。

## 凭据：只有两处来源，仓库里一处都不留

飞书 webhook、webhook 地址、签名密钥，全部**只从设置项或环境变量取**，没有第三处，也没有内置默认值。
两处都空是一种**状态**（`missing-config`）而不是错误：面板上把缺的那一项名字写出来，等人去填。

`test/nudge.test.js` 里有一条测试专门守着默认值全是空串——这类东西一旦被谁「顺手填个默认值」提交进来，
就再也洗不掉了。

**邮件为什么不做直连 SMTP**：Obsidian 插件里没有 SMTP 客户端，硬做要么引第三方依赖、要么自己写协议，
还要把邮箱密码存进 vault 里的 `data.json`。收益和风险完全不成比例。通用 webhook 指向自己的中转
（n8n / 云函数 / 另一个机器人）是更短也更安全的路。**这是取舍，不是没做完。**

## 禅定盖的是休息段，不是工作段

这一条曾经理解反了，值得留个记号。

0.6.4 之前的实现是「工作段全屏遮罩」，背后藏着一个没说出口的假设：**禅定 = 让人远离电脑**。
放在这个系统里，这个假设是错的。仓库主人用电脑、用 Obsidian 的时候，正是在**工作**——
电脑和 Obsidian 是生产力工具，是主要阵地；真正该在休息时放下的是手机那一类娱乐工具。
把工作台盖住，等于**锁住干活的地方、放过所有玩具**，方向整个反了。

禅定在这份设计里的位置是明确的：**一段活干完之后的休息、锁定、静心时间**。它挨着工作段的
**尾巴**，不是骑在工作段身上。所以 0.6.5 起，遮罩默认只在休息段出现；工作段要盖得有明确的
意思表示（设置里长开，或用命令临时叫一次，只对当前段有效）。

顺带把这块遮罩的边界写死：**它是休息页，不是锁屏**。一块 Obsidian 内的 `position: fixed`
盖不住浏览器，更盖不住手机——拿它冒充锁屏，只会强化上面那个反过来的方向。所以系统级锁屏
关着的时候，休息页底下会直说这件事，并把人指向真正的锁屏开关。真锁在《锁屏：唯一不可逆的动作》。

至于「开始之前把心态调整一下」那个更小众的诉求，它不归禅定管，归**复工强提醒页**（R6）：
拦在工作段前面、有最短停留时间、拦着的时候番茄是停的。禅定收尾，强提醒页开场，一前一后。

### 附带修掉的一件事：停着的表看不出是停着的

休息段从前也吃「自动开始下一段」这个开关。关掉之后，休息段起来就是 `paused`，遮罩弹出来、
数字停在 `05:00` 一动不动，而状态栏那个 `⏸` **恰好被这块遮罩盖住了**——唯一的状态提示被
自己盖掉，于是只能被读成「倒计时坏了」。两条一起改：

1. **休息段一律自跑**，不看那个开关。休息的钟在工作结束那一刻就开始走了，等人点一下才走的休息
   不是休息。那个开关此后只管**开工**那一侧——手动的口子该留在开工前，而复工强提醒页本来就在那儿；
   （0.8.0 又往前走了一步：那个开关整个删了，开工**一律**等人。见下文《开工永远是手动的》。）
2. **遮罩自己得说话**：停着时数字变灰、副标题写「停着 · 按「开工」倒计时才会走」、
   按钮是高亮的「开工」。一块盖住全屏的东西，必须自带它盖掉的那些状态。

## 强提醒页为什么复用禅定那块遮罩

同一块屏幕上不该有两套盖法。两套的下场是两边的 Esc 语义、z-index 和退出路径各走各的，早晚打架。
所以 `ZenOverlay` 长出了三种模式，优先级写死：**锁屏倒计时 > 强提醒页 > 禅定**。
越不可逆的越靠前——倒计时要是被别的遮罩盖住，人就没机会按「推迟」了。

三种模式的 Esc 语义故意不同，且都有理由：

- 禅定：Esc 退出，**退出不停表**。休息页是给自己用的，不是关自己禁闭；
- 强提醒页：**Esc 不放行**。一按就走的「强提醒」等于没提醒。放行靠停留时间到；
- 锁屏倒计时：Esc = 推迟。不可逆的动作，反悔的口子一定要留着。

还有一条不那么显眼但更要紧的：**强提醒页拦着的时候番茄是暂停的**。不暂停的话，
人盯着这一页发呆的三分钟会被记成专注时间，账当场就假了——R1 到 R5 的数据可信度全靠这类小地方守住。

强提醒页留了「这次先跳过」（设置里可禁）。看起来是在削弱「强」，其实相反：
**锁死的界面第二天就会被整个关掉插件**，那前面五轮全白干。

它**只跳过这一次**，下一段休息完照样拦。这颗按钮从前叫「今天先跳过」，
而在默认的「每次复工」档下它一天都管不住，在「每天第一次复工」档下又把一整天全豁免了——
两种都不是那句话写的意思，所以 AME-273 把名字和行为一起改成了「这次」。
想整天不被拦，路是关掉强提醒页这个开关本身：**豁免要显式，不该是跳过的副作用**。

## 锁屏：唯一不可逆的动作

它和这个插件里其它所有功能都不同——遮罩关掉就没了，锁屏关掉要重新输密码；
锁在错的时刻（会议中、录屏中、跑长任务时）比不锁糟得多。所以三条：**默认关、锁前倒计时可取消、今天豁免一按到底**。

平台按分支给命令：macOS 走 `CGSession -suspend`（不需要辅助功能权限），Windows 走
`rundll32 user32.dll,LockWorkStation`。**Linux 明确做不到**——桌面环境太杂，
`loginctl` / `xdg-screensaver` / 各家自带命令各不相同，没在真机上验过的命令不写进来充数。
锁不动的机器上一次都不提：提了也执行不了，纯噪音。

命令表本身是 `src/core/lock.ts` 里的纯数据，能被测到；真正 spawn 子进程的那一下在 `src/desktop.ts`，
整个插件只有那一个文件碰 `window.require`，而且是懒加载 + 兜异常——拿不到就明说拿不到，不让整个插件挂掉。

## 强制干扰：不发声的强约束等于没有约束（0.7.0 / AME-238）

R6 造完之后，仓库主人报了一件事：休息结束，复工强提醒页把番茄拦住了，然后**什么都没发生**。
他去做家务、睡了两个多小时，回到电脑桌前**手动切到 Obsidian** 才发现番茄卡在那儿；
而那一页显示的是「看完了，开工」——停留倒计时按墙上的钟自己走完了，那一页根本没人看过。

一条 bug 拆成两件事，两件都得改：

1. **倒计时量错了东西。** 「最短停留」要量的是「人看了多久」，不是「这一页开着多久」。
   两者只有在人一直坐在屏幕前时才碰巧相等。
2. **拦住了，但没人知道。** R6 的推送在窗口之外说话，可它推的是「该休息了」这类**播报**；
   「番茄正卡在你身上」这件事没有任何一路会持续地喊。**推不动人的提醒等于噪音，
   不发声的强约束等于没有约束。**

### 分成三层，各管各的

| 层 | 文件 | 管什么 |
| --- | --- | --- |
| 判「人在不在」 | `src/core/attention.ts` | 两种「在」：在电脑前（`atKeyboard`）、在看这一页（`attending`） |
| 判「什么时候动手」 | `src/core/enforce.ts` | 阶梯状态机，只输出动作清单，不执行 |
| 真的动手 | `src/alarm.ts` + `src/desktop.ts` | 通知连击、蜂鸣、亮度闪烁、拽窗口、锁屏、开督促页 |

**两种「在」绝不能混成一个布尔**，它们触发的动作完全不同：混成一个的下场，要么是人在浏览器里
刷得正欢却被锁屏（锁掉的是他正在做的事），要么是人走了两小时、只因为窗口还开着就被判成「在看」——
后者正是这条 issue 报的。「在电脑前」的口径是**全系统**最后一次输入（Electron `powerMonitor`，
拿不到时退回 PowerShell 的 `GetLastInputInfo`），不是「Obsidian 窗口里有没有动静」。

### 阶梯

原话给的就是阶梯，照抄即可：收工前 3 分钟连击 → 进入休息先锁屏 → 休息结束没复工，
每分钟复查一轮，**空闲**才动用锁屏。三条硬规矩写在算法前面：

- **锁屏只锁空闲的机器。** 人在电脑前但没复工的那一路只拽窗口 + 连击，不锁。
- **催一小时就收手**（可配）。人真的去睡了，凌晨三点还在闪屏不是自律，是灾难。
- **每一轮都留痕。** 催了第几轮、为什么催、下一轮什么时候——面板上要答得出来。
  一层会自己锁屏、自己闪屏的东西，人有权随时看见它的下一步。

阶梯是纯函数，`test/enforce.test.js` 把每一条分支钉死：靠手工在真机上点一晚上，
验不出「第 7 轮还会不会锁」这种事。

### 倒计时怎么改的：推起点，不另记一本账

`advanceGateDwell` 每拍把**没算数的那一段时间加到 `openedAt` 上**，于是
`gateRemainingMs = openedAt + 停留时长 - now` 这条算式一个字都不用改，面板、按钮、进度条全跟着对。
另记一个 `attendedMs` 去判定的话，同一件事就有了两个真相，迟早对不上。

三个边角都在 `test/gate-dwell.test.js` 里：**看满就定格**（中途走开不倒扣，否则读起来像 bug）、
**掉拍不白送**（后台节流下一拍能跨一分钟，最多按 5 秒记账）、**关掉开关退回墙钟**（0.6.x 的老行为留着）。

### 为什么连击不走 PushHub 那五道闸

那五道闸是为了「别把人吵到把功能关掉」，按每条消息算冷却（默认 10 分钟）——
3 分钟的连击到它手里会被掐成 1 条。强制干扰是人自己点名要的吵闹，所以直接走系统通知，
只留一道闸：**人明确按下的静音**（而且静音只停通知和响声，亮度闪烁与锁屏照旧——
静音管的是「别吵」，不是「别管我」）。

通知用同一个 `tag` + `renotify`：每次都重新响，但通知中心里只留一条。90 条独立通知会把通知中心
刷成一整屏，第二天人就会去系统设置里把 Obsidian 的通知整个关掉——那才是真的失去这一路。

### 亮度闪烁：为什么是一个长命 PowerShell 进程

Windows 走 WMI（`WmiSetBrightness`），波形照原话 `100 - 80 - … - 0 - … - 80`，每档 400 毫秒。
**整段闪烁由一个进程跑完**，不是每档起一个：起一次 PowerShell 要 200–400 毫秒根本排不上，
更要紧的是它自带 `Start-Sleep`，**扛得住 Chromium 的后台节流**——人切走之后 Obsidian 是隐藏窗口，
渲染进程的定时器会被压到每秒一次、五分钟后每分钟一次，而「人切走了」正是最需要这段干扰的时刻。
（同一个理由，强制干扰开着时插件会调 `setBackgroundThrottling(false)`，卸载时还回去。）

被中途叫停时进程是被 kill 的，跑不到脚本结尾那句还原，所以**杀完由插件补一条还原命令**：
不补的话人会得到一块停在 20% 亮度的屏幕，而且完全不知道是谁干的。

**WMI 只管内置显示器**，外接屏走 DDC/CI 够不着。那种机器上明说「调不动」，退回遮罩 + 任务栏闪烁，
不假装成功——这和锁屏那条「做不到就说做不到」是同一条规矩。macOS 的亮度这一版没做：
先把 Windows 一端做稳，再谈兼容其它端。

### 为什么不复用老的 `lockEnabled`

老那条路（R6 的「休息段提议锁屏」）默认关，而且**已经以 `false` 存进了仓库主人那台机器的
`data.json`**——改它的默认值对那台机器一点作用都没有。新功能挂在新键上（`enforce*`）才吃得到新默认值。
两条路各有各的开关，互不干扰。

## 开工永远是手动的（0.8.0 / AME-239）

同一条线上的第三次报障，这一次的话说得最重：

> 【开工】永远是 人类手动的行为（【自动开工】永远是无法被接受的！）
> 如果 “应该开工而没有开工” 则应该 永远是提示！！！

拆下来是三件独立的事，三件都改了：

### 1. 自动开工那个开关整个删掉，不是改默认值

0.7.0 的 `autoStartNext` 默认开着：休息一结束，工作段自己跑起来。人还在厨房，
表已经在替他计专注时间——**账当场就假了**，而且强制干扰那一层也不会催（它只在「停着等人」时才催）。

删掉而不是把默认值改成 `false`，有两个理由：改默认值救不回已经把 `true` 存进 `data.json` 的那台机器；
而**一个能被打开的自动开工开关，迟早会被打开**。休息段那一侧没变，仍然一律自跑（见 AME-231）。

### 2. 「催了 60 分钟之后自己变成【看完了，开工】」的真正来路

0.7.0 刚修完「倒计时只在人真的看着时才走」，同样的现象又出现了一次。来路是**插件自己**：

催促的每一轮都会 `focusMainWindow()` 把 Obsidian 拽到人脸前，而 0.7.0 把 `window` 的 `focus`
事件也算成一次输入。于是在**拿不到系统空闲时间**的机器上（Electron remote 不通、PowerShell 兜底也失败），
attention 退回「窗口内最后一次输入」这条兜底口径，读到的正是插件自己刚刚制造的那一下——
**倒计时是被自己的催促推完的。**

两条修法：**焦点不是人**（只认指针 / 键盘 / 滚轮），以及**锁屏和拽窗口之后一律先当作没人在**，
直到真的有一次手上的动作。第二条尤其硬：刚被插件锁掉的机器前面，没有人在看任何东西。

顺带说清楚一件事：就算倒计时真的走完，那也只是**按钮变得可点**。工作段永远不会因此自己跑起来——
第 1 条已经把那条路封死了。

### 3. 收手改成一颗开关，默认不收手

0.7.0 默认「催满一小时收手」，写在代码里的理由是「凌晨三点还在闪屏不是自律，是灾难」。
理由没错，但那是**插件替人决定「可以放过自己了」**。所以它变成一颗单独的开关
（`enforceGiveUpEnabled`，默认关），时限只在开关打开时才算数。

又是一个**新键**：老机器的 `data.json` 里那个 60 早就存下来了，改默认值对它没有任何作用。

### 4. 面板上只剩「开工」和「结束」

> 【暂停】————这是没有任何需要和必要的……也不符合我们的设计哲学。
> 【跳过本段】————完全是【不明所以】……这和我们的强制性干预的原则，是完全违反的。

「跳过本段」不只是从界面上摘掉按钮，**动作本身也从状态机里删了**——留着的话，
下一个人迟早会把它再接回某个界面上去。要提前收工走「结束」，那一段照实记成未完成。

`pause` / `resume` 留在状态机里，但**不再有任何人类入口**：它们是强提醒页拦人时停表、
以及一段跑完之后等人开工用的内部动作。

## 存在感：悬浮框、心跳、任务栏（0.8.0 / AME-239）

> 中间的提示太弱了，几乎没有存在感——我的预期，每 2 分钟 得有一个提示、提醒？

R1–R6 把「说话」全押在两个地方：Obsidian 窗口里的遮罩，和出事时才炸一轮的强制干扰。
中间是空的——**人切到别的窗口干活的那 25 分钟里，这套系统在他视野里根本不存在**。
补的这一层定位很窄但要一直在：

| 手段 | 看得见的前提 | 强度 |
| --- | --- | --- |
| 桌面悬浮框 | 什么窗口在前台都看得见 | 常驻、弱 |
| 任务栏进度 / 闪烁 | 余光扫得到任务栏 | 常驻、更弱 |
| 心跳（默认每 2 分钟） | 系统通知 | 周期、中 |
| 强制干扰 | 亮度闪烁 / 锁屏 | 事件驱动、强 |

三条实现上的硬约束：

1. **常驻的那两条一律不可交互。** 悬浮窗 `setIgnoreMouseEvents(true)`、不抢焦点、不进任务栏。
   一块能挡住鼠标的浮层一天之内就会被关掉，而它的价值恰恰在于「一直在」。
2. **秒表由悬浮窗自己走。** 插件只在状态变了时推一次（跨进程每秒喊一次纯属浪费），
   那一页拿到的是一个终点时刻，自己 `setInterval` 走秒——**插件这边被 Chromium 节流也不影响它准不准**。
   反过来，**停着的表不给终点**：一块自己往前跑的倒计时正好会让人以为「番茄在跑」。
3. **开不出桌面窗就退回窗口内浮层，而且说出来。** 「以为它一直在，其实切走就没了」比没有这个功能更坏。

**真正的系统托盘图标插件够不着**（`Tray` 要在主进程建、要 nativeImage、要有人管生命周期，
而插件跑在渲染进程里）。够得着的是任务栏按钮上那条进度：工作蓝、休息黄、欠着开工红。

心跳**绕开 PushHub 那五道闸**，理由和连击那一条一样：按冷却 10 分钟算，2 分钟一拍的节拍
第一拍之后就全被吃掉了。只留一道闸——人按下的静音。正在被强制干扰时心跳让路，两层不叠。

## 界面字号：一个全局倍数（0.8.0 / AME-239）

> 整体的字体，应该要大一点——因为我的 Obsidian 面板的【Zoom Level】，是缩放到了【83%】左右。

所以它是**一台机器一个数**（默认 1.2 ≈ 1 / 0.83），不是一堆各自为政的字号，也不写进任何落盘数据。
插件往 `document.body` 挂 `--life-cockpit-scale`，每一块界面只在根节点换算一次，里面一律用 `em`。
挂在 body 而不是各个视图上，是因为遮罩和悬浮层直接挂在 body 下——挂在视图上它们吃不到。

设置页自己**不吃**这个缩放：只把自己几节放大，会和设置窗里其它插件的排版打架。

## 重启是家常便饭，所以状态要跨重启（0.9.0 / AME-244）

> 我是一个会经常折腾 Obsidian、包括重启 Obsidian 来让各种插件调整和生效的人；所以【Obsidian】重启，是像家常便饭一样的事情。

在这句话之前，「挂着的任务 / 目标只是当前选择，不落 `data.json`」是一条有意为之的规矩——
少一份要维护的状态。**这一版把它推翻了**：如果重启是家常便饭，那么「重启就清空」不是简洁，
是每天丢好几次状态。

真正难的不是存下来，是决定**离开的那段时间算不算专注**。两头都是错的：

- **全算**：关了三小时回来白得三小时专注。AME-239 刚判过同类的事（「人还在厨房，表已经在替你计专注时间」）。
- **全不算**：重启一次 20 秒，番茄从头开始——那正是这条报障在抱怨的。

所以按段的性质分：工作段有**宽限期**（默认 5 分钟，重启一次通常十几秒），超过就**就地冻住**，
离开的时间一秒不算，回来自己按开工；休息段不看宽限期，它按墙上的钟走（人不在正好是在休息），
离开期间跑完了就照实补记那一段，然后停在「等你开工」。跨过归日点的段整段作废，不回头补记昨天的账。

两个跟着来的判断：

- **回来之后是「停着等你」，不是「继续跑」。** 离开很久回来和休息结束还没复工是同一种状态，
  所以它走同一条路：进待命、被催、复工前先过强提醒页。开工永远是人手动的这一条没有例外（AME-239）。
- **补记用存下来的计划时长**，不是现在设置里的：已经跑过的那一段不该因为你后来改了设置而变长变短。

实现上，现场和设置同住 `data.json`（`saveData` 是整份覆盖，所以两者必须一起写），跑着的时候
每 15 秒刷新一次时刻——正常退出有 `onunload` 收尾，被任务管理器结束掉时就只丢最后那十几秒。
判断全在 `src/core/session.ts`，被 `test/session.test.js` 按上面每一格钉住。

## 两种模式的基准时长为什么对调（0.9.0 / AME-244）

> 思考 需要更多的思考和调节时间、连续思考 45 分钟 是不现实的；而【加速实践】更多的是一种冲劲，连续 45 分钟 是一种正常的表现。

于是思考优先从 45 + 10 换成 **25 + 5**，加速实践从 25 + 5 换成 **45 + 10**。换的是**整组节奏**
（工作 / 休息 / 长休息 / 几个一轮 / 提醒间隔），不是只挪工作时长那一个数：25 分钟的段配 30 分钟的
提醒、45 分钟的段配 45 分钟的提醒，本来就是配好的两对，拆开会得到「一段跑 45 分钟、中间被主题
提醒打断两次」。提醒主题不跟着走——那几句写的是这个模式的心法，和它跑多久无关。

**改默认值救不回已经存过一次的机器**（这是 0.8.0 那一轮的教训），所以这次加了 `settingsVersion`
并写了一段一次性迁移。它只认「五个数字一字不差等于旧默认值」的那一台机器，自己调过就原样留着——
和 0.6.x 那次路径迁移是同一条规矩。有世代号是因为对调之后**新旧两组值都是合法配置**：
没有它的话，人以后有意把时长调回旧的那一组，还会被再翻一次。

## 间歇节奏：为什么它和长休息的轮数无关（0.9.0 / AME-244）

> 此处，为了简化 和长休息的轮数无关 ，就是每天 第一次 45 分钟，之后第二次减半，第三次又是 45 分钟 这种。

所以口径就是**单双数**，不是「第几轮」：第 1、3、5 个跑基准时长，第 2、4、6 个减半。
两个跟着的决定：

- **跟着的那一小段休息一起缩。** 原话要的是「自动切换 节奏**和间歇**」；只缩工作不缩休息，
  得到的是另一种节奏，不是他说的那一种。
- **长休息不缩。** 那一段是给身体的，不是给节奏的，而且原话点名它和轮数无关。

默认关：它是一种节奏偏好，不是默认作息——原话说的是「增加一个【切换】」。

## 新手 / 专家：为什么是「灰着」而不是「藏起来」（0.9.0 / AME-244）

> 【可配置项】实在是太多、太复杂了（就连我这个设计者，看上去 很多选项不自己亲手折腾一下，也会不知道啥意思）。

到 0.8.0 为止，设置页十七节、上百个选项——它们每一个都有来路（几乎都是某一次报障的落点），
但摊在一起就成了一堵墙。分档不是把选项删掉，而是**先给出一个能直接用的默认面**。

划线的规矩只有一句：**新手模式下能改的只有两类——「这台电脑的显示偏好」和「这一层功能要不要」。**
换一台电脑就要重调的东西（字号）不给改等于不能用；而每一层的总开关是**反悔口子**——一个会锁屏、
会闪屏的插件，人必须随时关得掉它，哪怕他还没搞懂下面那二十个参数。剩下的（催几轮、闪多久、
账本落在哪）恰恰是「不自己亲手折腾一下也不知道啥意思」的那一批，它们有默认值。

**灰着而不是藏起来**（原话「灰色的不许修改、仅查看」）：藏起来的话，人连「原来这个东西可以调」
都不知道，那是另一种形式的复杂。

实现上有一个选择值得记：「哪些项在新手模式下能改」是**在建这一项的时候标记号**的
（`openInBeginner`），不是在别处按名字对表。按名字对表的话，改一句文案就会有一项悄悄地锁死，
而那种 bug 没人会发现——人只会以为「本来就不让改」。没标记号的一律锁上，所以新增一项的
默认结果是「改不了」，而不是「悄悄能改」。

档位切换排在设置页最上面、每一页都看得见，而且它自己永远不灰：新手模式下满屏都是灰的，
切档的开关要是也躲在某一页里，人只会以为这个插件坏了。

## 结束本段不该把强约束一起关掉（0.10.0 / AME-258）

同一条线上的第四次报障。前三次修的是「它不该自己往前跑」，这一次相反——**它不该就这么停下**：

> 我发现，在【手动结束一个番茄】之后，不会有后续的【提醒、介入】什么之类的——
> ta 就那么一直停在那儿了？这个不符合我的预期，我的预期是
> 【不管是自然完成还是结束；强干扰和提示 仍然会照规则存在的。】

原因在状态机里：`stop` 直接把表推回 `idle`，于是插件层一路收摊——`clearAwaiting()` 清掉待命、
`abandonGate()` 作废强提醒页、`enforce` 归零。**一颗长得只像「这个番茄我提前结束」的按钮，
把 R6 那一整层关掉了**，而且关得毫无声息。

修法不是给它补几条提醒，是**把这一颗按钮拆成两件事**：

| 动作 | 状态机 | 在哪儿 |
| --- | --- | --- |
| 结束本段 | 走和跑满同一条 `advance`：工作→休息，休息→停在工作段等人 | 面板 + 命令面板 |
| 今天收工 | 新加的 `close-day`，**只有它发 `stopped`、只有它回 idle** | 只在命令面板，且确认一次 |

**为什么复用 `advance` 而不是在 `stop` 里另写一段**：两条路只要是两段代码，就一定会在某次改动里
长出差异，而那种差异表现为「自然跑完会锁屏，手动结束不会」——正是这次报障本身。
账目上的区别由 `snapshot` 自己算出来（提前结束 `completed: false`），不需要分支。

**为什么收工不放进面板**：它是全系统唯一一个能把催促停下来的动作。
「该开工而没开工就应该永远提示」那条规矩没有变，停的不是规矩、是今天——
一个能顺手按到的「今天算了」按钮，会在第三天变成每天都按的那颗。

顺带堵了一个洞：**一秒都没跑过的段结束不了**。休息刚完、工作段停着等人的那一刻按【结束本段】，
若放行就换来一段休息——那就是 AME-239 拿掉的「跳过本段」从后门回来了。

## AI 接口：一份档位表，不是一处写死的地址（0.10.0 / AME-258）

> 我希望能配置 AI 接口……（将来，可能会增加新的 AI 模型啥的，我希望都能便于配置）
> 你需要在本地源码中，有一个专门的模块——并且在 Obsidian 插件中，有相关的配置。

R5 当初写的是「AI 那一段接口留干净，换模型换渠道不动主体逻辑」——那句话兑现了一半：
接口确实干净（素材包 JSON 进、`ReviewDraft` 出），但**插件自己不会说话**，模型那一端一直得靠
外面的 Multica autopilot。这一轮把另一半补上。

形状照抄推动器，不新发明：

- **闸门与拼装在 core（`core/ai.ts`），发请求在外面一层（`ai-client.ts`）。** 于是「地址怎么拼、
  响应怎么读、缺什么算缺配置」全都测得到，`node --test` 里跑的是真的那套逻辑。
- **凭据只有两处来源**：设置项 → 环境变量。没有第三处，也没有内置默认值。仓库里一处密钥都不留，
  预置档位只带地址和模型名（有一条测试专门守着这件事）。
- **不能用是状态不是异常**：`disabled` / `missing-config` 分开说，面板上要答得出缺的是哪一样。

两个决定值得记：

**统一按 OpenAI 的 `/chat/completions` 形状来。** 现在能接的这几家（OpenCode Go、DeepSeek 官方、
各类中转）对外都是这一套；多一层自研抽象只会在换供应商那天变成两处要改。真遇到不兼容的，
那时再加一个 `dialect` 字段。

**模型 id 以端点自报的为准。** issue 里写的是「DeepSeek v4 0731 Flash」，
但 `GET https://opencode.ai/zen/go/v1/models` 上只有 `deepseek-v4-flash` 和 `deepseek-v4-pro`
（2026-08-18 实测）。照人话去猜 id 会得到一个 404——预置档位里写的是端点自己认的那个。

复盘草稿那一段跑不通时**退回兜底并明说是哪一种失败**（缺密钥 / HTTP 错 / 空正文 / JSON 读不出）。
这条规矩是从 S1 抄过来的：夜里静默降级比直接失败更难发现——第二天看到的是一份
「看起来正常但没有洞见」的复盘，没人会去查模型是不是根本没跑。

## 飞书表格：接一栏，不搬一张表（0.10.0 / AME-258）

> 飞书的金字塔表格，是一个非常适合我的表格；然后目前，我感觉 ta 很够用，
> **还不用完全重写内置到 Obsidian 里面**（而是我仍然在飞书表格上面做记录）。

所以这一层的边界是仓库主人自己划的：**记录继续发生在飞书上**，插件只接一个回执。

**不写飞书 OpenAPI 客户端。** 导出那条路已经有一条跑通的管线（GA 的
`feishu_daily_tasks_report`：`lark-cli sheets +export` → xlsx → 按单元格填色判完成度 →
`all_tasks.json`）。那条管线拿着 user token、认得那张表的版式；插件再写一遍只会得到一个更差的
第二实现，而且要把飞书凭据搬进 vault。**所以约定的输入就是那条管线已经在产的文件**——
拷进运行区的 `飞书快照/` 即可，格式一个字节都不用改。

三个显示位各有各的理由：

- **复工强提醒页**——被拦下来的那几秒是一天里最可能真看一眼的时刻，所以这一栏
  **没做完的排前面**，且排在推荐读物**之前**：先看「今天答应过要做什么」，再看「今天读点什么」。
- **驾驶舱面板**——只有一行状态和两颗按钮。它是外面那张表的回执，不在这里重画那张表。
- **复盘素材包**——带的是**原句**，不只是计数。番茄流水记的是时间去处，飞书表格记的是事情本身；
  「我每天大概干了什么、我是一个什么方向的人」这一问，只有原句答得了。

一个次序上的取舍：**当天没填表时退到「最近有记录的那一天」，并把日期写出来。**
只认当天文件的话，这一栏一年里有大半年是空的——而它要回答的那一问本来就不要求当天。

### 报告不另出一份，写回表自己身上（0.15.0 / AME-271 第 28 条）

> 你其实可以在那个飞书的 Excel 那个文档的 SOP 的 py 脚本，去让他自己去插入一页【总结】……
> 这样长期以来也是一个很大的一个人的 issue 库。

这条改的不是「显示在哪儿」，是**报告这个东西的形态**。从前的走向是「把表读进来，
在我们这边显示」；现在是「算完写回去，让那张表自己带着答案」。差别在于：
写回去的那一页，不开 Obsidian 也看得到，不连后端也看得到，agent 读那张表就顺手读到了——
它不需要先知道「还有个别的地方要去看」。

**写的人仍然不是插件。** 那一页由 `backend/life-cockpit/scripts/write_feishu_summary.py`
整页写进飞书，版式和口径在后端（`convex/lib/feishuSummary.ts`，`node --test` 钉住）。
插件这一侧只多了两样东西：设置里一个【总结】页地址、面板和命令面板上一颗
【打开总结页】；数据台上多一格回执（那一页新不新、还欠多少条）。

**为什么插件不在自己这儿再画一份清单**：同一份「哪些做了、哪些没做」画两遍，
迟早出现两份对不上的清单，而对不上的两份比只有一份坏得多。所以插件给的是一条路，不是副本。

边界与那一页上有什么，见[《飞书金字塔表格 · 快照约定》](飞书金字塔表格-快照约定.md)。

### 完成度只填一次（0.16.0）

> 最好目标的完成——也可以根据【飞书Excel】上面的来？免得我在【飞书Excel上手动更改了目标完成程度】
> ——本地OB插件还要手动来一次？

所以目标项上写了 `[飞书:: 关键词]` 的，**进度直接按表上命中的那些条目算**：
已完成算 1、完成了一部分算 0.5、其余 0。半个不是拍脑袋——表上那一档就叫「完成了一部分」，
算成 0 会让一支推了一半的目标显示成没动，算成 1 会让它显示成做完了，两边都在说谎。

取值顺序上它**压过度量和手写完成度**（绑关键词这个动作本身就是「这支的进度以那张表为准」），
但**排在子节点回灌之后**——树自己的语义优先，一支有子节点的目标仍然由子节点决定。
表上一条都没命中时安全降级回原来那几条，**不会把一支目标压成 0%**。

算的是**整张表**而不是某一天：徽章回答「今天这支推了几条」，进度回答「这支到现在做到哪儿了」，
后者跨所有日期页。没绑关键词的目标一条都不受影响。

**进度来源是飞书时，目标名后面会标一个「飞书」**——一个数字悄悄换了来源，
人只会以为自己填的完成度没生效。

## 秒哒：直接拉，但落地区归人（0.16.0 / AME-272 第 26 条）

> 把秒哒应用——接口，给直接接过来？ 放到 Obsidian 的插件中去……
> 1、比如，按日期来。日期之内，按大标题，放各个文章、档案。
> 2、这里，我更倾向于 保存到我的 Obsidian 里面，**给人看的区域的**。

**为什么这一层直接连 API，而飞书那一层坚决不连。** 两处看着矛盾，其实是同一条判断：
飞书那边已经有一条跑通的导出管线（拿着 user token、认得那张表的版式），插件再写一遍
只会得到一个更差的第二实现；秒哒这边**没有这样一条管线**，他给的就是一条现成的、只读的、
匿名 key 的接口。有现成管线就接管线，没有就自己拉——判断的依据是「哪条路更短且不搬凭据」，
不是「插件该不该发请求」。

**拉回来的是毛坯，不是成品。** 那个 APP 是什么，他自己写清楚了：头脑风暴（5 秒或 12 秒
不写就擦除）、手机语音输入（受部分识别的影响）。所以这一层**原文一个字不改**——
识别错的字、断掉的句子、重复的段落全部照抄。润色是以后他自己或某个 Agent 在候选区里干的事，
不是这一层的资格。段落上标着模式 / 状态 / 擦除倒计时几秒 / 这一段有没有撑住，
因为那个「不写就擦」的机制本身就是这份记录的一部分。

**这一层唯一的纪律：别跟他抢那一页。** 落点在给人看的那一块，而他明说了
「我可能会手动整理之后，放到飞书的 Excel 中的一些任务或者事项」——也就是说，
这一页上的东西**会被他搬走**。于是三条：

- **搬走的段落不补写。** `_同步索引.json` 记着哪一段写过、写去了哪一天、写的是哪个版本；
  页面上找不着了就是他搬走了，下一次拉取不补。**落地区因此是可以清空的**，
  而不是一个每次拉取都会长回来的收件箱。
- **手写的段落不碰。** 段落的边界是「后面跟着 `- 秒哒ID：` 的二级标题」，
  所以他自己加的段落、正文里恰好出现的 `## ` 都不会被当成同步单元。
- **重复拉取不写盘。** 页首不带「拉取于」这类每次都变的字段，索引按 id 排序序列化——
  落点在 2A-META 仓库里，一次假写入就是给 Easy Git 一个空 commit。

**分桶按「开始写」那一刻，不按 `updated_at`。** 这不是风格问题：实测远端做过一次批量迁移，
几十条七月的记录 `updated_at` 全被推到了同一天，拿它分桶会把七月的头脑风暴整片扔进八月那一页。
换日点复用账本日（默认 04:00），和运行区里其它几样对齐。

**「limit 放大一点、或者删除？」的答案是不用。** 增量靠 `updated_at=gte.<上次最新的>`——
索引记着上次拉到哪儿，之后每次只问动过的那几条，两百条也好两万条也好都一样快。
翻页按 `updated_at` **升序**：降序 + offset 在拉取过程中来了新记录就会漏掉一条。

**空白记录默认不落盘。** 实测 188 条里有 27 条是点开了没写（正文空、字数 0）。
落地区里塞 27 个空壳，人第一眼看到的全是噪音。设置里可以打开，而且跳过的从不进索引，
所以打开之后补得回来。

## 三处「名不副实」（0.17.0 / AME-273）

这一轮修的三条没有共同的模块，却是同一种毛病：**界面上写的那句话，和它实际干的事对不上。**
这类 bug 比功能缺失更贵——功能缺了人会绕开，说法错了人会按错的说法安排自己。

### 一、「今天先跳过」从来没跳过一整天

> 这个按钮的表述和实际功能，实际上不相符？（并且，其实没有【今天一整天都跳过】的这种需要）

强提醒页那颗跳过按钮，点下去走的是 `passGate`——和「看完了，开工」同一条路。于是：

- **默认档（每次复工）**：`passedDay` 根本没人查，下一段休息完照样拦。按钮说「今天」，实际管一次；
- **每天第一次那一档**：它反倒把**一整天**都豁免了——而这种需要压根不存在。

一颗按钮，两档设置，两种都不是它写的意思。所以拆成两个动作：`passGate`（看完了）记今天，
`skipGate`（没看）只收这一次的遮罩。名字也改成**「这次先跳过」**，两档下都是同一句话。

**豁免要显式，不能是跳过的副作用。** 真想整天不被拦，路是关掉强提醒页那个开关本身——
那是一个人明确按下的决定，而不是他随手点一颗按钮时并不知道自己按下了的东西。

### 二、密钥这条路上，人只能手抄

> ApiKey——我手动复制的，经常会多一个换行（在手动剔除了换行后，发现就可以了）

地址预置好了、落点预置好了，**整个配置里只有密钥必须由人手工搬运**。而复制这条路上什么都会跟着来：
末尾一个换行、`"apikey": "…"` 连键带引号、`Bearer ` 前缀、devtools 里多带的一个逗号、
从网页上刮下来的零宽字符。它们一个都不属于密钥，却每一个都换来一个 401——
**而 401 和「key 填错了」长得一模一样**，人无从判断自己错在哪，只能一个字符一个字符地试。

`core/secret.ts` 按他给的三条办：

1. **示例格式**：设置项里写明「`eyJ` 开头、两个点分成三段、不含任何空白」；
2. **干扰字符的提醒**：洗掉了什么当场说出来（「粘进来的内容里有换行，已自动去掉」）；
3. **自动去除**：空白（任意位置，不只首尾）、包裹的引号、标签前缀、行尾逗号分号。

洗的边界只有一条：**只动确定不属于密钥的字符**。base64url 的 `-` `_`、补位的 `=`、分段的点，
一个都不许碰——洗坏一把好 key 比脏着更糟，因为人还以为自己填对了。

密钥框下面还多了一行**形状**：「JWT（三段，点号分隔） · 218 字符 · eyJhbG…E4AA」。
密钥不回显（设置页是会被截图的地方），但填对没有必须能当场看见，
否则唯一的反馈就是那个不说人话的 401。这条洗法同时接在 `resolveCredential` 上，
所以 AI 接口、飞书那几处一并受益——**环境变量那一路更需要它**：`$(cat key.txt)` 天然带着换行。

### 三、悬浮窗比 Obsidian 活得久

> 点击【退出 Obsidian】后，插件的 Electron 悬浮窗还在（重新打开 Obsidian 后，又会启动第二个……两个窗会重叠）

这块贴纸是**另一扇真窗户**，不是 Obsidian 窗口里的一个 div——而它的寿命从前只挂在一个地方：
插件的 `onunload`。「退出 Obsidian」这条路根本不走那个钩子。主窗关了，这扇窗还开着，
于是 Electron 那句「窗都关完了才退进程」永远等不到：**进程活着，贴纸留在屏幕上，下次打开再叠一张。**
（走【重启 Obsidian】反而正常，因为它走的是另一套收尾——同一个 bug 的两种表现，
正好说明问题不在「关窗」而在「谁来关」。）

一扇置顶、点击穿透、不进任务栏也不进 Alt-Tab 的窗，人在系统里**连关它的地方都找不到**，
只能去任务管理器。所以寿命改成三条腿，任何一条断了另外两条还在：

| 腿 | 管的是哪种死法 |
| --- | --- |
| 主窗 `beforeunload` 时自己关 | 正常退出 / 重启 / 重载插件 |
| 开窗前按标题记号扫掉前任 | 上一条没跑成、或上一版插件留下的孤儿窗 |
| 贴纸自己的看门狗（5 分钟收不到心跳就自尽） | 插件被强杀、渲染进程崩掉 |

三条里最要小心的是第二条：**收窗不可逆，宁可漏收一扇孤儿窗，也不能误杀人家的 Obsidian 主窗。**
所以只认全等的标题、不做前缀匹配、并且绝不碰当前这扇窗。看门狗的余量给到心跳的 15 倍，
理由同样是宁可慢：Obsidian 切后台时插件那边会被 Chromium 压到每分钟一跳，
差得太近就会在人正看着的时候把窗关掉——那比孤儿窗糟得多。

## 每日推荐为什么按天轮换而不是随机

随机推荐在个人系统里是有毒的：今天推没推过、看没看完，第二天全说不清。
按天轮换的话，同一天里反复看到的是同一份，换一天必然换一份——「每天推荐」这四个字才落得下来。

料**不另造内容源**：候选区里 S1 夜班的 N 次方总结、R1 的休息页、R5 的复盘素材包，三处都是现成的。
读物池是可选的第四处，默认空，只是一串指向 vault 内已有笔记的路径。

**0.10.0 起读物池认目录**（AME-258 第 19.0 条）。原来只认单篇 `.md`，要读一整个目录得把每一篇
手抄一遍，目录里多一篇就得回设置里改一次——那不是配置，那是维护。现在不以 `.md` 结尾的一行
按目录展开，儒释道那一摊（`AI-First时代，知识库（toAI完全公开）/人文社会科学`）填一行就够。
展开结果**按路径排序**而不是按 vault 给的顺序：轮换是按天取第 N 个，顺序不稳的话
「换一天必然换一篇」就不成立了。

四类**轮着取**而不是按类排队：资讯多的日子，按类排队会把精品阅读和复盘挤得永远轮不上，
那这个功能就退化成了资讯推送。

推荐挂在强提醒页上，而不是另开一个面板：人被拦下来的这几秒，是一天里最可能真的看一眼的时刻。

## 明确不做的

- **直连 SMTP 发邮件。** 见上面的取舍说明；走通用 webhook 接自己的网关。
- **Linux 上的系统级锁屏。** 明说做不到，不用没验过的命令充数。
- **macOS 上的屏幕亮度闪烁。** 同一条规矩：先把 Windows 一端做稳。锁屏两端都有。
- **外接显示器的亮度（DDC/CI）。** WMI 够不着，那种机器上退回遮罩 + 任务栏闪烁。
- **真正的系统托盘图标。** 要主进程建 `Tray`，插件在渲染进程里够不着；退到任务栏进度 + 闪烁。
- **移动端。** `isDesktopOnly: true`。

## 落盘位置：一条硬边界

**驾驶舱属于 2A-META 仓库，它写出来的每一份东西都落在仓库内。**

理由不是洁癖，是交班链：番茄流水、积分账本、目标树、候选区、复盘素材、复盘日记——夜班 Agent
全都要能读、能写。两库之间只有一条**只读**的引用桥（RefBake 把外部片段烘进仓库），没有反向通道；
落到仓库外，人这边看得见，AI 那边够不着，R4 / R5 的人机交班当场断掉。

```
Root/【2A-META】AI-First时代，知识库（toAI完全公开）/   ← 仓库根 = AI 够得着的范围
  驾驶舱运行区/          ← 插件的数据面，全在这儿
    番茄流水/  积分账本/  目标树.md
    候选区/    复盘素材/  复盘日记/
    资讯收件箱/  飞书快照/
  AI史书/AI时代错题本-不贰过.md    ← 主干知识，不进运行区
  资讯/日报/                        ← 资讯采纳落点，同上

Root/每日Journal/       ← 仓库主人**纯人**的地盘，插件一个字都不往这儿写
```

> 这张图是**作者自己 vault 的布局举例**，不是对所有人的硬性要求：数据面在哪个目录，
> 以 Life Cockpit 插件设置里的那个数据根为准——插件 0.19.0 起默认数据根是中性的
> `LifeCockpit/`（作者的旧布局叫 `驾驶舱运行区/`），下面的层级结构两边一样。

常量在 `src/core/settings.ts` 的 `REPO_ROOT` / `COCKPIT_ROOT`，断言在 `test/settings-paths.test.js`。
**新增任何写盘设置项，默认值都要挂在 `COCKPIT_ROOT` 下面**，那个测试会拦住落到仓库外的。

有三类设置**不受这条约束**，因为它们是「你自己挑的一页」而不是插件的数据：休息页、复工强提醒页、
读物池、背景音乐。这几项默认都是空，填哪儿都行——包括指回你自己的 `Root/每日Journal/`，
插件只是在 Obsidian 里打开给你看，AI 不读。

### 从 0.6.3 及以前升上来

旧默认值（`Root/每日Journal/番茄流水`、`Root/候选区` 那一批）会在加载设置时**一次性自动迁到运行区**，
只认「一字不差等于旧默认值」——自己改过的路径原样留着，改过就是有意的。

**迁的是设置里那个字符串，不搬盘上的文件。** 老位置已经有数据的话自己挪一次（或者不挪，
在设置里把路径改回去也行）。

## 待仓库主人在 vault 内确认

1. 五行列映射默认取「周一到周五」是否合意（见上）。
2. 三类休息页（冥想 / 精品阅读 / 健康养生）的笔记路径需要在设置里填，默认为空。
3. 运行区整块会随 2A-META 仓库公开。资讯那部分本来就抓自公开频道；番茄流水、积分账本、
   复盘日记是你的行为记录——要是哪天不想公开，把 `驾驶舱运行区/` 整个挪成一个私有仓库、
   在 vault 里平级挂着即可，插件只认路径，改设置就行。收件箱会天天长，要不要定个保留期。
4. 默认任务表的分值（番茄 2 分、深工作 12 分、刷视频 -12 分……）是照六维任务清单拟的**初值**，跑几天不顺手就直接改 `积分任务表.md`，不用改代码。
5. 候选区要和 `tools/news-inbox` 的 `candidatesFolder` 保持一致——两边指到不同目录，夜班落的东西拍板面就看不见。拍板留痕里的「操作者」默认写 `人`，想署自己的名在设置里改。
6. **复盘正文落的是运行区里驾驶舱自己的 `复盘日记/`，不是你 `Root/每日Journal/日记/` 里的私人日记。**
   复盘是人机共有的产物（AI 出草稿、你拍板），所以它跟着驾驶舱走；私人日记插件不碰。
   想让复盘并进私人日记的话，把「日记目录」改回去就行——但那样 AI 就读不到复盘历史了。
7. 睡前提醒时间默认 22:00，和节律表里睡觉段的起点一致。改作息就一起改。
8. **推动器的凭据一处都没有填**，这是有意的。系统通知不需要凭据、默认就开着；飞书和通用 webhook
   默认关，要用的话在设置里填地址（等于写进 vault 里的 `data.json`），或改用环境变量
   `LIFE_COCKPIT_FEISHU_WEBHOOK` / `LIFE_COCKPIT_FEISHU_SECRET` / `LIFE_COCKPIT_WEBHOOK_URL`。
9. **复工强提醒页要看的那一页默认是空路径**——最可能想填的是日记模板里那张《今日每日任务》。
   停留时间默认 8 秒、允许跳过；嫌短嫌长在设置里调。
10. **强制锁屏默认关。** 开之前先在自己那台机器上按一次命令面板里的「立刻锁屏」试试：
    macOS 上如果只熄屏没锁，是系统的「唤醒时要求密码」没开，不是插件的问题。
11. **运行时音乐默认关，也没有预置任何曲目**——《常成 - 狮子吼六字真言》这类文件要自己放进 vault，
    再把路径填进设置。插件不内置音频。
12. 每日推荐默认 08:30 推一次（三小时工作日开工前半小时），一天 3 条。读物池默认空。
13. **强制干扰默认开着**（0.7.0）——这一条和上面第 10 条的「强制锁屏默认关」不冲突，两条是两条路。
    装上之后**先跑一次命令面板里的「演练一次强制干扰（20 秒）」**：当场看得到连击 + 蜂鸣 + 亮度闪烁，
    不用等二十几分钟。台式机 + 外接显示器的话亮度多半调不动，设置页里有「测一次亮度」按钮，
    调不动会退回遮罩 + 任务栏闪烁。
14. **「进入休息先锁屏」默认开着，留 5 秒反悔。** 会议 / 录屏那几次记得在倒计时里按「推迟」或「今天豁免」；
    想要更硬就把秒数设成 0（立刻锁）。
15. **督促自律网页默认为空**——插件不编造地址。留空时那一格会改成把 Obsidian 拽到前台，
    填了地址就用系统默认浏览器打开它。
16. **催不到人默认不收手**（0.8.0）。想留退路：设置 → 强提醒 · 锁屏 · 干扰 → 「催不到人就收手」。
17. **悬浮提示与心跳默认开着**（0.8.0）。装上先去设置 → 界面 → 悬浮提示按一下「闪一下」：
    它会当场告诉你这台机器上是**桌面悬浮窗**还是退回了**窗口内浮层**（后者切走就看不见）。
    心跳默认每 2 分钟一条；嫌吵就把「番茄正常跑着时也提醒」关掉——「该开工却没开工」那一格不受影响，
    那一条永远响。
